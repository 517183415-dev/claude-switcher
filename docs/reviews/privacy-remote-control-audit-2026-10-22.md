以下为旧版更新机制。本机定时触发已停用；手动 `update` 仍可触发图中的下载、替换与执行流程。

```text

          |
          v

          |

          |
          v

          |
          v

```

### R-02：外部时区先写入脚本，再进入管理员命令——条件性代码执行风险

`core/claude-switch.sh:242–262` 从第三方地理服务读取 `timezone`。该字段仅检查非空。`set-region` 还检查国家与 IP，见 `:773–775`。

| 阶段 | 代码与触发时机 | 权限条件 |
| --- | --- | --- |
| 写入脚本 | `:780–784` 将时区写入脚本自身的 `TZ_TARGET`；该步骤发生在系统授权之前 | 当前用户可写脚本，替换成功 |
| 后续普通调用 | 脚本再次执行顶部 `:147` 赋值时，合法 shell 命令替换语法可能被执行 | 当前用户权限；普通检查等调用即可读取赋值 |
| 地区设置提权 | `:792–799` 将时区拼进管理员 shell | 还需要 macOS 管理员授权 |

用户态路径需要：攻击者控制一个被采用的地理服务响应；响应通过国家/IP 条件；用户执行 `set-region`；脚本写入成功；之后再次执行普通脚本路径。写入步骤本身保存文本，命令在后续解析赋值时触发。取消管理员授权仍会留下此前完成的脚本修改。

此前审核把风险统一描述为“需要管理员授权”，遗漏了上述用户态阶段。本次修正该结论。正常 TLS 校验仍约束响应控制能力；DNS 控制本身尚不足以绕过证书验证。

这条数据流与项目仓库的控制权分别成立。Rust 版应把时区视为数据，通过本机时区列表验证，再调用固定系统操作。

### R-03：修复会提升用户可写服务配置的权限——条件性提权链

`core/claude-switch.sh:703–704` 在系统保镖服务查询失败时，读取 `~/.local/bin/local.claude-bodyguard.plist`。随后生成复制到 `/Library/LaunchDaemons/`、更改所有者与注册服务的命令。`:709–710` 通过系统授权执行这些命令。

成立条件包括：攻击者先取得该用户目录的写入能力；代理、TUN 和出口前置检查通过；系统服务查询失败；用户批准管理员操作；launchd 接受修改后的 plist。恶意更新取得用户权限后，可能成为这条链的前置来源。

本机用户目录中的该 plist 确实可写。当前两个系统守护服务都已注册，故本次采样中的服务缺失条件未出现。`launchctl(1)` 说明修改 system domain 需要 root 权限；服务主动卸载还需相应权限。

Rust helper 接受固定业务动作。安装材料从已验证的包获取，并校验客户端身份与操作数据。验收应覆盖伪造用户 plist 和非授权调用方。
