## 审核基线与归因

旧版基线采用 R4 接手时的受保护工作区，不采用 Git HEAD 单独推断。当前旧 core、Swift 界面、守护和安装器的哈希仍匹配接手基线。45 个受保护文件中 42 个未变；三个变化仅在 experiments/p0 的两个已知构建错误与配置修复范围内。

旧版文件相对 Git HEAD 的部分差异，接手时已经存在。不能把这些历史安全修复算成本轮 Rust 新增。当前 Rust 大量文件尚未进入独立 Git 提交，无法逐行证明准确的修改时间和执行者；下面以源码行为与留存候选记录为证，不编造逐次编辑历史。

“当前规格依据”表示在现行 v1.2 找到了要求。你最初授权执行当时的 v1.2。能确认当时已存在的要求属于初始范围；现行文档新增内容及实现细节，不能据此追溯为已授权。两份文档后来有过调整，当前文字不能单独证明首次授权时已存在，更不能证明你逐项选择了实现细节。文档中的“已有 Rust 安全边界继续保留”也不能代替你的逐项决定。

当前只核对源码。旧源码能力不等于旧服务仍在运行；当前候选行为不等于已安装 r17 的真实行为。r18 是未安装候选。本次不运行这些行为。

下表的 **71 项是审核问题，不是 71 个独立功能或 71 个已证明的安全缺陷**。同一功能的触发条件、门槛和失败处理分别编号。除 P01／P02 已有明确决定外，其余逐项待审；“功能缺口”不伪装成安全增强。

## 写代码过程复盘：哪些反复安装来自缺陷

这些记录解释 r12—r18 的过程。它们不等于用户要求增加新功能。表中的通过结论是历史记录，本轮没有重跑。

| 阶段 | 留存记录中的主要变化／问题 | 本次应如何看待 |
| --- | --- | --- |
| E01—早期候选 | 从实验骨架实现四包、检查、账号事务、helper／guardian、更新与广告模块 | 新架构本身有初始授权；不能因此认定旧行为已经等价 |
| r12 | 本地身份安装、旧服务交接、CLI 修复转发；安装先遇到 Darwin 用户组恢复错误 | 安装器缺陷造成重试；不是旧版业务功能 |
| r13 | 受限 Clash 用户进程重启；真实修复被备份新增 provenance 属性阻断 | 严格属性比较引入兼容问题；不是账号资料损坏证据 |
| r14 | 偏好复制等价与恢复收据修正；真实系统修复后检查通过到局部状态 | 修复上一候选缺陷，不代表完整账号切换完成 |
| r15 | 迁移心跳竞争和 Surge 失败意图修正；又遇摘要类型错误与系统原值记录误拦安装 | 既有门槛加准备脚本缺陷，造成多次要求你重试 |
| r16 | 接受安全的旧 accounts/0755 容器，保持旧权限 | 修复新校验拒绝旧布局的问题 |
| r17 | 账号复制产生 provenance 的等价规则与严格工件绑定；真实备份／隔离恢复完成 | 只证明备份阶段；没有证明首次 A 或 A→B→A 已完成 |
| r18 | 修复普通界面读取使备份绑定过期；补事务忙后的时区短重试 | 尚未安装。暂停后没有继续安装，也没有把它当真实通过 |

频繁输入密码的根因不是每个旧功能都需要新密码。D01／D02／D06／D08 将每个新候选的替换、代码指纹登记和健康判定接在管理员安装流程中。上述缺陷又增加了重试次数。此前没有先把不需管理员的分支集中收敛，就多次要求安装，这个执行顺序增加了你的操作负担。
