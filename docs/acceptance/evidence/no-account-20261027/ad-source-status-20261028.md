# 广告内容来源状态与刷新提示：隔离回归

## 范围

工作区快照按广告运行层实际选择的来源报告状态。已配置来源不表示内容已发布、网络可用或签名验证通过。无效配置保留错误提示，不显示为缺少配置。刷新提示按等待原因区分广告位关闭、缺少来源、本机未发布、时间状态和刷新时机。

## 结果

| 检查 | 结果和边界 |
| --- | --- |
| 来源状态 RED | 合成发行来源有效时，旧快照错误地报告远程未配置；断言失败。 |
| 刷新提示 RED | 广告位关闭时，旧提示错误地要求在 Personal 发布；断言失败。 |
| Public 特性、无发行来源 | 快照回归通过；分别检查 Personal 和 Public 的缺失来源、有效本机信任和无效本机信任。 |
| Public 特性、合成发行来源 | 快照回归通过；分别检查两版对发行来源与本机来源的选择。尚无有效缓存时不展示广告。 |
| Personal 特性、无发行来源 | 同一快照回归通过，检查两版运行状态。 |
| 核心来源状态 | 选中、缺失和配置错误三种状态的定向测试通过。 |
| 刷新提示 | 两版关闭广告位、缺少来源、尚未到刷新时机、时钟恢复和本机未发布的提示回归通过。 |
| 快照测试输入保护 | 测试夹具识别空配置和指定的合成配置；部分配置或其他配置明确报错，不再静默返回成功。这是测试输入限制，不代表产品的发行配置错误路径已验收。 |
| 静态检查 | 变更 Rust 文件的 rustfmt 检查通过；Public 目标 Clippy 使用 `-D warnings` 通过。 |

测试使用临时目录、合成公钥和 `ads.example.com`。测试沙箱禁止外网，允许回环连接。它不读取真实账号、默认 Keychain 或真实远程服务。系统启动标识在该沙箱不可读取，因此刷新提示只直接测试状态映射，本轮没有验证完整的手动刷新调用。

快照测试在不同构建条件下分别运行同一个测试名；这不是多个不同测试。候选包未包含本轮修改，真实 R2、发布、签名传播和窗口业务操作仍待验证。测试原始输出保存在本机 `output/no-account-20261027/ad-source-status-6cHkZury/`。
