# 正式渠道备份恢复后的远程续发

测试使用合成资料、合成密钥和本机模拟对象存储。发布路径使用实际的 AWS S3 工具包，网络仅允许回环访问。没有连接 Cloudflare。

1. 先发布正式版本并导出加密备份，再发布一个更高版本。将素材从模拟服务移除，模拟素材缺失。
2. 在独立目录恢复旧备份并重新打开发布器。恢复期间没有远程请求，已发布内容保持不变。
3. 模拟服务返回签名被篡改的 current 时，发布器报告 `signature`，没有上传素材、版本或 current。
4. 恢复正确的 current 后，发布器读取并验证远程版本，补传素材，以旧 ETag 条件写入更高版本，并匿名回读 current、版本与素材。
5. 接收端使用正式渠道配置和公钥验签，读取并校验素材，采用恢复后的版本。

受影响的 SDK 测试组先运行 5 项通过、1 项测试进程入口忽略。随后仅将坏签名断言收紧为明确错误码，并单独重跑新增测试，通过。严格 Clippy、改动文件格式及差异空白检查通过。日志有既有 ts-rs 属性解析提示，不计为零警告。

模拟服务只检查合成认证头的格式，不验证服务端 AWS 请求签名。接收端测试使用回环 HTTP 和受控时钟，不运行生产 HTTPS 客户端或后台定时器。重新打开的是同一测试进程中的发布器对象，不证明完整 App 重启。默认 Keychain、真实 R2/CDN、线上传播及完整 AD-10 验收仍未验证。注册、部署和付款保持暂停。
