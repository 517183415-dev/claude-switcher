# SwiftUI 产品接入与无需账号验证（2026-10-28）

本轮把原生 SwiftUI 页面接入两版产品构建。产品继续通过本地 Tauri 桥使用现有 Rust 业务和权限。初次验证基于提交 `6e8522dec18fb0ffcb8d592c45cdbe96dfcbf1a6` 加本轮工作区改动；大文件测试基于提交 `dc7e20a8` 加测试夹具改动。下方机读记录保存夹具的相关源码哈希。验证后仅删除 `OverviewView.swift` 文件末尾的一行空行；机读记录保存变更前后哈希。测试机为 macOS 27.0.1 arm64。

## 验证结果

1. Swift 测试：22 项通过，含广告预览字段、延迟结果、恢复操作锁和文件读取缺陷回归。
2. Rust 工作区 `--tests`：顶层 935 项通过、7 项忽略；另跳过 2 项系统相关测试。日志里另外有 3 次嵌套单测，不计入顶层总数。Public 桌面另跑 175 项通过、1 项忽略；该数字与工作区测试可能重叠。两版 IPC 特性的严格 Clippy 通过。
3. 隔离原生窗口：Personal 验证原生宿主、桥、工作区、发布状态及小体积 Base64 输入到正式 IPC；Public 验证工作区、隐藏发布入口和一条发布命令的后端拒绝。两版使用合成资料和 MemoryVault，不连接真实账号或网络。
4. 两版 arm64 产品包构建成功，原始包通过严格深度签名检查。签名为本机临时签名，未公证。隔离启动检查仅确认每个普通产品进程存活并创建自己的窗口，不证明窗口内的各项业务成功。
5. CodeGraph 完成同步：303 个文件、7,449 个节点、29,532 条边，待处理变更为 0。

补充边界测试：Personal 隔离窗口通过 Swift 恢复模型和 WebView 传输 64 MiB 合成无效备份。Rust 返回备份头无效，草稿保持不变，恢复锁解除。另通过命令桥直接发送 64 MiB 加 1 字节，后端返回超限错误。此测试绕过界面的超限保护，以验证后端边界。

[机读记录](swiftui-native-20261028.json)保存测试摘要、夹具检查、所选源码哈希、产品二进制哈希和日志哈希。原始日志、截图和产品包位于本机 `output/no-account-20261027/swiftui-final/`；大文件测试原始结果位于 `output/no-account-20261027/swiftui-large-backup-r1/`。这些原始文件未纳入 Git。Public 单独测试与工作区测试不应相加作为不重复测试数。
