# 生产运营 IPC 密钥边界与备份闭环

1. 在现有 security 模块封装应用级 ManagedVault，默认使用 KeychainVault。Personal 的 Tauri Builder 单独管理此服务，生产命令经 State 注入；Public 不注册此服务。DesktopState 不依赖运营密钥模块，保留四个独立桥接集成测试的编译边界。仅测试可构造合成 Vault，不增加 IPC、配置开关或依赖。
2. publisher_commands 和 publisher_recovery_commands 统一经该边界访问 Vault；Publisher 锁先于 Vault 锁。PreparedRecovery 会话保持原锁和确认合同。复用 MemoryVault，新增生产分发表的密钥、发布、导出、恢复和重建状态测试，独立核对文件及密钥不被覆盖。发现 bug 先复现并补回归。
3. 现有已有效的 233 项桌面测试是改前依据，不重复基线。先定向验证新增业务闭环，阶段末集中执行两版适用桌面集合、Clippy 和变更格式检查。记录合成 Vault / MockRuntime 与真实 Keychain / WebView / R2 的区别。

```text
普通 IPC → 生产 handler → Publisher 锁 → ManagedVault → KeychainVault（默认）
                                                  └→ MemoryVault（仅测试构造）
```

文件范围：main.rs、publisher/security.rs、publisher_commands.rs、publisher_recovery_commands.rs、ipc_dispatch_tests.rs、ipc_dispatch_tests/publisher_backup.rs，更新图谱、PRD、覆盖映射和本地 Git。现有命令名、ACL、前端 JSON 参数与返回类型保持不变；新增的 Vault 参数仅由 Tauri State 注入。注册、部署、付款暂停；不启动子代理。UI 最后执行，保留当前布局。
