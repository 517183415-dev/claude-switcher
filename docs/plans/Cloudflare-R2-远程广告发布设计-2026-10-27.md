# Cloudflare R2 远程广告发布设计

状态：**设计与本地开发中，尚未完成接线或上线**。日期：2026-10-27。

本文描述广告内容的远程发布。软件自身安装包更新是独立链路，不在本设计的交付范围内。当前不能据此宣称用户已能收到远程广告或自动升级软件。

用户已明确允许为 R2 接入添加 AWS 官方 SDK。账户注册与付款暂缓。先完成不依赖真实账户的功能，再单独编写防攻击方案供用户核对；本文的风险边界不能视为该方案已获用户认可。

## 1. 目标与现状

Personal 操作员发布后，软件自动上传内容、核对公开版本及素材。Public 客户端自动刷新，验证签名、版本和素材，再按排期展示。发布发生冲突、签名无效或结果无法确认时，软件不报告成功。

```text
Personal 草稿 → 签名 → R2 条件写入 → 匿名回读
                                        ↓
Public 定时读取 → 验签和版本校验 → 校验素材 → 展示
```

当前发布命令只装配 `LocalObjectStore`。工作树中有尚未接线的 R2 适配器，并已使用本机协议替身进行部分测试；这不证明真实 R2 可用。`ObjectStore` 已定义有界读取、匿名回读、不可变创建和 current 条件更新。R2 目标标识区分账号、存储桶、公开域名和渠道，不包含写入凭据。现有 Personal 密钥包由 Keychain 保存；客户端已有内容验签和版本防回退逻辑，并支持构建期注入发行域名和验签公钥。真实生产材料尚未配置，因此当前 Public 无法接收正式远程内容。

软件自身更新的 `compiled_release_pins` 也尚未配置。不能将广告版本核对当作安装包版本检查。

### 接线前阻断：发布目标状态尚未隔离

原有 Pending、ETag、版本水位和历史没有按发布目标隔离。直接在本地存储与 R2 间切换，可能把一个目标的事务用于另一个目标，也可能因水位而拒绝 R2 首次发布。工作树中的候选隔离逻辑尚在审查，并存在旧状态和跨目录备份缺少迁移入口的兼容问题；远程目标仍被拒绝。此问题是接线前阻断项。以下描述是目标，不代表已经完成。

保留单一 Publisher、单一锁、共享草稿、图片和签名能力。以经过验证的稳定目标身份隔离事务、版本水位、历史和恢复。目标身份须绑定可信的目标配置，不能接受任意未经验证的输入。凭据轮换不改变目标身份；目标发生实质变化时不能复用其他目标的状态。

旧事务如果无法证明来源，必须保留并拒绝自动恢复或继续发布。迁移不得猜测其目标，也不能覆盖或丢弃旧数据。备份和恢复按目标合并状态，冲突时保留资料并停止；清理必须保护所有目标引用的素材和历史。共享草稿生成新版本时，序号取全部目标水位中的最大值，再按既有安全规则递增。

目标隔离目前尚未完成。严格 Clippy 检查尚未通过。两项均不得作为远程功能可用或可上线的证据。

### 来源不明旧事务：完整加密恢复规格

以下方案全部**待实现、待测试**。现有 `export_backup` 会省略 cleanup、checkpoint、quarantine 和未索引素材，因此不能充当整个旧 generation 的完整备份。

1. 对整个旧 generation 与相关 Keychain、trust 建立版本化清单。清单记录相对路径、类型、长度和摘要，以及恢复所需的版本关联；不得在明文日志或清单中暴露秘密。
2. 扫描与读取期间拒绝符号链接、硬链接和未知类型。遇到不安全项时保留原数据并停止，不能跳过后声称备份完整。
3. 对完整恢复材料加密。写入后读取密文，解密并逐项核对清单、摘要、类型和关联关系。只有全部核对通过，才能进入用户确认阶段。
4. 整个确认和切换流程持有发布锁，并固定已验证的根目录与实例身份。向用户展示与该次备份、源实例和目标操作绑定的确认摘要。确认后的输入或实例发生变化时，丢弃该次确认并重新核对。
5. 原子切换有效 generation。远程 current 的 CAS 应延迟至本地恢复材料和状态可恢复之后。每个切换或 CAS 中断点都必须能在重启后识别结果；结果未知时保留事务并停止，不能推断成功或失败。

旧 generation 和旧 Vault 条目永不自动清理。故障、取消或重启不得删除旧资料。任何人工清理必须另有明确授权与可验证的恢复边界。

## 2. 发布协议

1. 发布前检查草稿、渠道、签名密钥、受限写入凭据和当前远程版本。preview 与 production 使用独立存储桶和各自限制到对应存储桶的凭据。
2. 上传按内容寻址的素材与版本文件。不可变对象使用创建条件；已存在时仅在内容一致并经过核对后复用。
3. 用读取到的 ETag 对 current 执行 `If-Match`。首次创建使用 `If-None-Match: *`。412 表示冲突；停止并要求重新核对，不能直接覆盖。
4. 关闭 SDK 自动重试，避免在结果未知时重复条件写入。上传超时或断连时，结果可能未知。保留待恢复事务，读取并验证实际对象与版本；读取到 404 本身不能证明先前写入不会完成。未经确认不能重发覆盖或报告成功。
5. 通过独立、匿名的公开读取路径回读 current、版本文件和素材，不复用带写凭据的读取。验证内容与签名。只有回读成功才报告发布成功。受缓存影响时保留恢复状态，不把暂时的旧内容当成发布成功。

R2 支持上述条件写入；实际错误、超时和并发语义须在受控真实服务中复验。[R2 条件写文档](https://developers.cloudflare.com/r2/api/s3/extensions/)

## 3. 安全和费用边界

- Personal 的广告签名私钥与 R2 写入凭据存放在受控密钥存储。日志、错误、备份和界面不得泄露凭据。Public 包不包含写入凭据和签名私钥。
- 公共客户端只获得经过发行审核的固定 HTTPS 来源、公钥、密钥 ID 和渠道。不得让普通 IPC、偏好设置或任意 URL 替换信任根。测试要覆盖现有本地信任与生产信任的优先级，避免意外覆盖生产信任。
- 最小化写入权限，并隔离 preview 与 production。现有协议要求凭据限制到对应环境目录；接入前须核实 R2 能否提供同等细粒度权限。若无法限制前缀，应采用独立存储桶及相应范围凭据，并测试越权拒绝。
- 正式公开读取使用受保护的自定义域名。通过缓存、WAF 和限流减少源站请求；关闭或限制可绕开保护的 `r2.dev` 公开入口。缓存 current 时必须明确更新延迟和旧 404 行为；素材可按不可变内容策略缓存。客户端限频不能阻止攻击者直接请求公开地址。[公开桶](https://developers.cloudflare.com/r2/buckets/public-buckets/)；[限流](https://developers.cloudflare.com/waf/rate-limiting-rules/)；[缓存默认行为](https://developers.cloudflare.com/cache/concepts/default-cache-behavior/)
- R2 请求和存储超过免费额度会产生费用，其他相关服务也可能收费。预算提醒只发送通知，不是硬费用上限；限流有延迟，也不能保证零费用。成本熔断若启用，必须明确其触发条件、权限和服务中断影响，不能假设已经存在。[R2 价格](https://developers.cloudflare.com/r2/pricing/)；[预算提醒](https://developers.cloudflare.com/billing/manage/budget-alerts/)

## 4. 分文件实施计划

以下是计划，不代表文件已变更。用户已授权添加 AWS 官方 SDK；实现前仍须核对版本、依赖、离线构建和平台能力。其他新增依赖按项目规则处理。

| 文件或区域 | 计划职责 |
| --- | --- |
| `apps/desktop/src-tauri/src/publisher/` | 新增 R2 存储适配器。复用 `protocol.rs` 和现有发布事务；通过明确的运行时边界将 AWS SDK 的异步调用适配当前同步 `ObjectStore`，避免在已有运行时内嵌套阻塞。实现受限读取、不可变写入、ETag 条件写入、独立匿名回读及明确错误映射。关闭 SDK 自动重试，并将写入超时映射为结果未知。 |
| `apps/desktop/src-tauri/src/publisher/` 的状态、备份、恢复与清理逻辑 | 保持共享 Publisher 和锁，先完成按稳定目标隔离的事务、水位、历史和恢复。迁移旧状态时保留来源无法证明的事务；备份按目标合并；清理检查所有目标引用。 |
| `apps/desktop/src-tauri/src/publisher_commands.rs` | Personal 端装配已审核配置的远程存储。保留本地发布兼容；不得由未受信输入任意选择写入目标。 |
| `apps/desktop/src-tauri/src/publisher/security.rs` | 复用受控密钥存储，并明确 R2 凭据格式、隔离和清理；不把凭据交给命令行或写入日志。 |
| `crates/switcher-core/src/ad_runtime.rs` 及受信发行配置 | 从经审核的发行材料注入真实来源、公钥及渠道；维护本地与生产信任的明确选择规则。无有效生产材料时继续拒绝远程生产内容。 |
| 发布器与 `ad_runtime` 测试目录 | 增加隔离协议、签名、缓存、失败恢复及两版本信任边界测试。真实服务验收与离线测试分开记录。 |

实际 R2 账户、独立存储桶、公开域名、写入凭据和发行公钥尚未确认。不能填入虚构生产值。签名私钥的生成、备份和轮换须另行明确操作与恢复步骤。R2 的 S3 兼容端点、区域及令牌权限以 [S3 API 文档](https://developers.cloudflare.com/r2/api/s3/api/) 和 [R2 API 令牌文档](https://developers.cloudflare.com/r2/api/tokens/) 为准。

## 5. 验证计划

### 不需要真实账户

在隔离目录和本地协议替身中，使用合成密钥和数据。覆盖成功上传、首次创建、并发冲突、ETag 不匹配、404、权限拒绝、限流、超时、截断、超限、TLS 拒绝及无意重定向。对写入前后断连、结果未知、进程中断和重启恢复分别检查事务状态与远程对象；不得只验证调用次数。

覆盖清单或素材篡改、错误公钥、过期清单、版本回退、缓存旧内容、错误渠道和素材哈希不符。验证客户端不会接受错误内容，并保留仍有效缓存或占位。验证失败不会影响账号功能。对发现的每个 bug 保留复现与回归测试。

核对 Public 不含写凭据和签名私钥。核对 Personal 凭据不会出现在日志、错误或不受控持久文件。核对本地与正式信任优先级、两种发行的权限及固定来源。协议替身只能证明本地实现，不能证明 Cloudflare 实际兼容。

接线前先增加能在旧实现上失败的回归，再修复并确认通过。至少覆盖：本地 Pending 不得被 R2 恢复、R2 Pending 不得被本地恢复、目标各自的 ETag 和水位不交叉、旧水位不错误阻止新目标首次发布。记录实际 RED 与 GREEN；没有复现证据时不得标记通过。

迁移测试应覆盖来源可验证和不可验证的旧事务。不可验证时保留原事务并 fail closed。另测备份按目标合并与冲突保留、清理跨目标引用保护、共享草稿使用全目标最大水位，以及轮换凭据后目标身份和待恢复事务保持一致。测试正常、故障和中断恢复；所有数据使用隔离目录与合成凭据。

完整加密恢复还须测试现有导出遗漏的 cleanup、checkpoint、quarantine 和未索引素材；验证新方案确实包含并能逐项读回。覆盖符号链接、硬链接、未知类型、密文损坏、缺项、错误密钥、确认摘要过期、根目录或实例替换。覆盖加密写入、读回、确认、原子切换和远程 CAS 各阶段的故障及进程重启；逐项验证旧 generation、旧 Vault 和原事务仍可保留。测试均为待实现，不得以现有导出测试替代。

### 需要真实账户或发行材料

在用户完成账户开通并明确费用后，配置独立受控存储和域名。验证真实 R2 的权限范围、TLS、条件写入、冲突、未知结果恢复、公开回读、缓存和 WAF 规则。记录计费及告警的实际设置和限制；不得把提醒写成自动停费。

账户注册和付款当前暂停。完成不依赖真实账户的功能后，应单独提交防攻击方案供用户核对；在此之前不把缓存、WAF 或其他防护措施视为已部署。

在真实发行公钥和签名流程准备好后，验证 Personal 发布到 Public 客户端的端到端传播。连续在线且源健康、首轮成功时，沿用 PRD 的公开回读后 20 分钟内采用目标。真实账单、防刷效果、公开部署、发行签名及客户端运行结果分别记录；未执行时保持 `NOT_RUN`。
