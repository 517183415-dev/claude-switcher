# Cloudflare R2 防攻击与费用控制方案

状态：**待用户审核的方案**。日期：2026-10-27。

Cloudflare 会自动识别和缓解一部分分布式拒绝服务攻击。它不会替本项目自动配置完整的访问控制、费用控制和应急流程。本方案尚未部署，也没有验证实际防护效果。用户已暂停注册；付款前须先请用户审核本方案和实际结账页面。

## 1. 先了解钱从哪里产生

```text
用户打开软件 → 读取公开的广告清单和图片 → 可能产生存储读取费用
用户点击广告 → 打开广告目标页面         → 是否收费取决于广告协议

攻击者 ──直接请求公开地址──→ Cloudflare 防护和缓存 ──未命中──→ R2
                              ↓                              ↓
                         拦截部分请求                    可能产生读取费用
```

广告点击本身不等于 R2 按点击收费。软件读取广告清单和图片时，R2 的读取操作可能计费。广告商是否按点击向用户收费，需要另看广告协议。R2 存储和操作超过免费额度后可能收费；其他产品或域名也可能产生费用。[R2 价格](https://developers.cloudflare.com/r2/pricing/)

攻击者可以绕过软件，直接请求公开地址。因此，软件自身的刷新间隔不能单独阻止刷请求。签名可以帮助客户端拒绝被篡改的内容，但签名不会拦截刷请求。

## 2. 建议的防护

| 措施 | 要做什么 | 必须保留的限制 |
| --- | --- | --- |
| Cloudflare 基础防护 | 让正式公开域名经过 Cloudflare，并查看 DDoS 防护事件。 | 自动缓解不等于能识别所有恶意请求，也不等于零账单。[DDoS 防护](https://developers.cloudflare.com/ddos-protection/) |
| 保护公开入口 | 为正式读取配置自定义域名，配置可用的 WAF 和限流。关闭独立的 `r2.dev` 公开入口，避免绕过正式域名的规则。 | 存储桶默认私有。公开配置、规则能力及费用应在实际账户和套餐中逐项核实。[公开存储桶](https://developers.cloudflare.com/r2/buckets/public-buckets/) |
| 缓存 | 为版本化图片及其他不可变内容配置缓存，减少回源读取。为会变化的版本清单单独设置较短缓存或经验证的失效机制。 | 默认缓存规则不一定缓存 JSON。旧清单、旧 404 和缓存传播可能延迟更新；发布后须通过用户相同的公开地址核对。[默认缓存行为](https://developers.cloudflare.com/cache/concepts/default-cache-behavior/)；[R2 一致性](https://developers.cloudflare.com/r2/reference/consistency/) |
| 限流 | 根据真实正常访问量设定规则，先观察再调整；记录触发情况和误拦截。 | 计数与缓解存在延迟；分布式攻击可能使用很多来源。限流不能保证所有请求被拦截。[限流规则](https://developers.cloudflare.com/waf/rate-limiting-rules/) |
| 权限与签名 | 管理端使用范围最小的写入凭据和独立签名私钥；用户端仅包含验签公钥。隔离测试和正式资源。 | 不能把写入凭据或签名私钥放进用户端。不能把签名验真当作防刷措施。[R2 令牌](https://developers.cloudflare.com/r2/api/tokens/) |

## 3. 费用监控和应急

1. 开通后核对 R2、域名、WAF 及其他关联服务的实际计费项目。启用可用的用量与预算提醒，并确认通知能送达。
2. 记录正常情况下的请求量、读取操作、缓存命中、拦截事件和费用。用这些基线识别异常；阈值应按实际访问量确定。
3. 请求异常时，先查看来源、命中率和 WAF 事件。根据事件调整限流或规则，并检查正常用户是否受到影响。
4. 异常持续或费用不可接受时，由授权人员执行预先演练过的应急操作，例如关闭公开读取入口。关闭期间用户可能无法获取新内容；缓存或正在处理的请求也可能延续，不能假定费用立即停止。
5. 事件结束后核对账单、规则与访问日志。必要时轮换受影响的写入凭据，再逐项恢复公开服务。

Cloudflare 的预算提醒仅用于通知。它不会暂停使用或设置费用硬上限。账单可能在提醒之前或之后继续增长。[预算提醒](https://developers.cloudflare.com/billing/manage/budget-alerts/)

**不能保证零费用，也不能保证费用存在自动硬上限。** 若将来设计自动关闭功能，须单独验证触发延迟、权限和恢复流程，并明确其对用户的影响。当前没有已验证的自动费用熔断功能。

## 4. 上线前核对清单

以下均为计划项目，当前不能标记为已完成。

- [ ] 用户核对本方案，并确认可接受的月度费用和异常处理方式。
- [ ] 用户完成 Cloudflare 注册；在任何付款、订阅或域名购买前，查看实际价格并自行决定。
- [ ] 用户审核账户、域名、公开范围和凭据权限。需要建立或扩大安全敏感访问时，再按实际操作请求确认。
- [ ] 配置正式域名、缓存、WAF 与限流；关闭独立的 `r2.dev` 入口。检查其他入口是否能够绕过规则。
- [ ] 从外部验证正常读取、规则命中、误拦截、旧版本和旧 404 的处理。核对公开回读和签名失败时的行为。
- [ ] 验证用量数据、通知送达、应急关闭和恢复。记录生效条件与服务中断影响。
- [ ] 在受控环境验证真实 R2 发布、签名和客户端接收。分别记录防护、账单和端到端测试结果。
