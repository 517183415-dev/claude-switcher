## 1. 产品目标与用户

产品帮助 macOS 用户管理 Claude 本地账号档案，检查启动条件，并执行可恢复的启动、切换和修复。

项目所有者使用 Personal 自用版，掌握软件发布与广告发布。其他用户使用 Public 对外版，接收产品更新和三个广告位的内容。

| 角色 | 核心任务 | 产品结果 |
| --- | --- | --- |
| 当前项目所有者 | 保存已有账号 A，检查并启动；手动安装批准的版本 | 资料保留、状态清楚、发布权可查 |
| 对外版用户 | 初始化档案、切换账号、诊断连接、接收更新 | 正常使用期间状态明确，失败后能恢复 |
| 广告运营者 | 管理三个广告位，安排下一期，发布、暂停与恢复 | 常规广告更新通过运营页完成 |
| 发布负责人 | 构建、签名、验收、发布和回退 | 每个版本有工件、来源与证据记录 |

用户当前只有一个账号。首次使用流程以该账号完成 A 的初始化和启动。B 保留为空档案状态。

## 4. 功能要求

### 4.1 环境检查与启动

| ID | 稳定检查 ID | 证据 | 策略 |
| --- | --- | --- | --- |
| CK-01 | proxy_process | 指定代理适配器识别的进程与服务状态 | 必需 |
| CK-02 | tun_route | TUN、活动网卡、路由和网络代次 | 必需 |
| CK-03 | egress_region | 有效出口与匹配的目标国家 | 必需 |
| CK-04 | ip_continuity | 首次基线或后续出口变化记录 | 提示项 |
| CK-05 | timezone | 本机时区与已确认目标 | 必需 |
| CK-06 | locale | 地区格式与已确认目标 | 必需 |
| CK-07 | ipv6_policy | 活动网络服务的实际策略 | 必需 |
| CK-08 | dns_route | 解析器、结果和适配器证据 | 必需 |
| CK-09 | stun_path | 来源、事务标识、长度、地址族和出口匹配 | 必需；全超时为待确认 |
| CK-10 | guardian | 注册、协议、心跳与进程状态 | 必需 |
| CK-11 | service_routes | 版本化服务域名清单及实际路由证据 | 必需 |
| CK-12 | client_language | 用户确认的客户端语言目标 | 必需 |
| CK-13 | asn_info | 服务来源和查询时间 | 提示项 |
| CK-14 | service_transport | TLS、传输完成和 HTTP 状态 | 必需；认证/访问状态另行展示 |

每项返回状态、原因、证据时间、耗时和有效期。缺项、重复 ID、必需项失败或待确认时，启动任务保持等待。IP 变化和 ASN 暂缺采用提示策略。仅 ASN 暂缺时显示“13 项通过 · 1 项提示”，以及“网络运营商信息暂未获取”。

401 显示“需要认证”。403 显示“服务器返回访问限制”。详情保留传输、访问与账号状态各自的证据。账号可用性由实际登录流程确认。

| ID | 要求 | 验收锚点 |
| --- | --- | --- |

| AC-03 | GUI、CLI、更新任务共享写入锁 | 并发用例 |
| AC-04 | 目标资料就位后，单次替换 active-state 提交对象，再生成兼容 current 镜像 | 哈希、目录身份和事务状态 |

### 4.3 修复、后台与诊断

修复计划列出每项变更、当前值、目标值、权限及恢复动作。用户取消系统授权时，页面显示取消，保留已验证的兼容状态。

guardian 使用用户级身份，监听网络变化和 2 秒兜底检查。helper 使用 root 身份，执行固定时区、网络和服务动作。helper 接收经过签名身份验证的 XPC 请求。每消息签名、连接 EUID、激活 UID/会话、角色和操作分别校验。双发行交接与授权取消按工程合同第 4 节验收。

独立诊断只使用明确选择的代理。诊断结果采用结构化数据。环境变量代理继承、SOCKS DNS、TLS 错误、超时和 HTTP 分类分别验收。

## 6. 三广告位与运营

### 6.1 固定广告位

| ID | 名称 | 独立字段 |
| --- | --- | --- |
| residential_broadband | 美国家庭宽带 | 商家、文案、图片、链接、排期、开关 |
| account_service | 注册好的账号 | 商家、文案、图片、链接、排期、开关 |
| kyc_service | KYC 服务 | 商家、文案、图片、链接、排期、开关 |

三位各显示一条当前内容，各可准备一条下一期。清单最多保存六条排期记录。时间统一保存为 UTC，编辑时默认显示 America/Los_Angeles，并允许运营者选择其他时区。单个广告位的排期冲突在发布前提示。

每张卡片标明“广告”。首次点击显示商家及域名，再打开系统浏览器 HTTPS 页面。商家或域名变化时重新确认。商家链接随签名广告更新；产品内容源域名由应用发行固定。服务说明沿用已审方案的官方授权账号服务和用户本人实名协助要求。

### 6.2 运营状态和发布流程

| 状态 | 可执行动作 | 对外展示 |
| --- | --- | --- |
| 草稿 | 编辑、保存、预览 | 维持当前正式内容 |
| 待发布 | 查看变更和环境、签名发布 | 维持当前正式内容 |
| 发布中 | 查看进度与发布编号 | 维持完整的已提交清单 |
| 待确认 | 按同一发布编号回查 | 根据远端实际提交状态恢复 |
| 已发布 / 已暂停 | 排期、再次编辑、恢复历史 | 使用最新有效签名清单 |

```text
选择广告位 → 编辑当前期/下一期 → 共用组件预览
                                      ↓
上传素材 → 保存签名版本 → 条件提交 current → 公开入口回读
```

发布并发采用基准版本比较。基准改变时提示合并。素材与不可变版本先上传。完整 payload 和签名放在同一个 current 对象中。恢复历史内容生成更高序号。

### 6.3 刷新、缓存和请求

| 场景 | 要求 |
| --- | --- |
| 正常在线 | 从上次成功校验固定下一次时间：15 分钟 + 当周期一次 0–60 秒随机延迟 |
| 启动/唤醒 | 已到计划时间立即补查；否则按剩余时间调度；同进程合并请求 |
| 正常传播 | 公开回读成功后，持续运行且首轮刷新成功的健康在线客户端在 20 分钟内采用 |
| 失败重试 | 1、5、15、30、60 分钟退避，之后每 60 分钟重试 |
| 手动刷新 | 30 秒节流 |
| 离线 | 缓存期限为上次成功检查后 24 小时、广告结束和清单到期三者的最早时间 |
| 全部关闭 | 停止清单及素材请求；独立诊断与软件更新遵循各自设置 |
| 单位关闭 | 停止该位素材获取；其他开启广告位维持调度 |

清单固定路径，查询参数为空；本机筛选地区和广告位。清单最多 256 KiB。图片采用静态 PNG/JPEG/WebP，压缩数据最多 1 MiB、像素最多 200 万、解码工作预算 16 MiB。分配像素缓冲前检查尺寸与溢出；显式识别 APNG/动画 WebP；实际解码遵守工作预算。超限和验证失败时显示本地占位。

时间异常时收起广告。恢复使用同一自控产品域名的固定 `/time.json`，查询参数为空，采用 no-store 与 CDN 绕过。恢复结合系统校时、连续 Date/Age 采样、单调时钟与最新签名内容，见工程合同第 6.3 节。广告全关时停止广告时间恢复请求。紧急暂停对在线用户在下次成功刷新采用；离线用户按现有缓存上限处理。

广告请求的数据合同为固定字段和公开素材。应用 Cookie、账号资料、设备 ID、地区和语言字段外发次数为 0。曝光与点击统计首版保存于本机。系统浏览器访问商家时使用的公开活动编号单独登记。

运营写入凭据与广告私钥在运行时保存于运营者本机密钥存储；分发包只携带相应公钥。软件签名和广告签名使用独立密钥。远端内容按固定 schema 解析，保持为数据。
