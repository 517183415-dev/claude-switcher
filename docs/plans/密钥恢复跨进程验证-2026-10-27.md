# 密钥恢复跨进程验证

1. 只扩展测试模块。保持产品逻辑、默认 Keychain、ACL、依赖和 UI 不变。
2. 协调进程创建 output 下的全新私有 Keychain。写入进程执行正式 Publisher 加密备份及恢复，然后完全退出。协调进程确认退出并回收后，才启动新读进程。
3. 新读进程重新打开私有 Keychain 和 Publisher，检查恢复代次、恢复待确认状态、旧密钥及恢复密钥、旧状态摘要、禁止自动发布。记录不同 PID 和退出码，不输出密钥。
4. 沿用显式启用保护、隔离 HOME、Seatbelt、禁止交互。只清理本次私有库中的精确条目；正常和 panic 后均清理库并核对默认库与搜索列表。
5. 定向运行新增原生用例、启用保护、编译、Clippy 和格式检查。产品源码及依赖不变时复用上阶段 236 项有效结果。更新图谱、PRD、覆盖索引及本地 Git。

```text
协调进程 → 创建私有库 → 写入进程：备份/恢复 → 退出并回收
         → 新读进程：重新打开/验证 → 退出并回收
         → 精确清理 → 偏好快照核对
```

范围：直接 Publisher + 正式 KeychainVault 的显式私有库分支。此测试不证明用户默认库权限、成功 WebView、整机重启或远程传播。UI 仍在最后，保留当前布局与非蓝紫色背景；注册、部署、付款暂停。

执行结果：一个验收测试通过；两个 worker 顺序退出码均 0。新增两个入口默认忽略，缺少启用提前拒绝。定向编译、Clippy、格式通过；复用既有 236 项完整测试。权限 fixture 的 RED/GREEN 已保留；旧资料与临时库清理、偏好快照均已核对。详见本阶段回执。
