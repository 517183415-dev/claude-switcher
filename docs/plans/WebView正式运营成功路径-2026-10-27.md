# WebView 正式运营成功路径

1. 复用 ipc-business 编译边界。新增显式模式与启用参数，只把合成 MemoryVault 注入应用。沿用正式 ipc::handler 和原 capability；不注册测试命令，不改变正式默认 Keychain、产品逻辑或依赖。
2. WKWebView 使用本地测试前端调用真实命令，依次生成密钥、导入规范化素材、编辑三槽六期、两渠道发布、加密备份、发布较高暂停版本、错误口令拒绝、恢复旧备份、明确续发。
3. 本地回执服务器仅处理固定路线。检查点由宿主独立读取合成目录；不接受路径输入。独立 Node 验证 Ed25519 签名、current/immutable 一致、序号、素材摘要和权限；核对拒绝不变、旧代次保留及恢复不自动发布。
4. 使用已有 Seatbelt 加 WebKit 数值回环解析器例外。禁止外网、真实 Claude 资料、系统 Keychain 和系统修改。测试通过回环回报结果，超时后只回收本次直接子进程。保留运行日志、输入摘要、失败和成功回执。
5. 只运行相关 Rust、测试工具检查及原生成功用例。有效完整测试与 ACL 矩阵沿用旧证据。阶段末更新图谱、PRD、覆盖索引和本地 Git。

```text
测试前端 → WKWebView → 正式 ACL / ipc::handler → 正式 Publisher 命令
                                                ↓
                                  合成 MemoryVault / 本机对象存储
宿主检查点 ← 固定回环路线 ← 测试前端回执
       ↓
独立签名 / 状态 / 素材 / 不变性核对
```

范围：真实 WebView + 正式处理函数，合成密钥库和测试前端。默认 Keychain 权限、普通产品前端、R2/CDN、整机重启和完整分支覆盖仍另验。UI 最后，沿用当前布局与非蓝紫色背景；注册、部署、付款暂停。
