# 原生密钥库恢复验证

目标：用真实 Security.framework 验证 KeychainVault 的独占创建与备份恢复；不读取真实 Claude 登录资料。

1. 仅新增 macOS、Personal、测试配置下的忽略测试。显式测试环境参数与全新私有合成目录是前置条件；默认测试集合不接触 Keychain。
2. 使用现有 KeychainVault，服务名保持正式实现。随机代次由生产生成器创建；测试只读取本次成功创建的条目。记录无秘密的条目清单。限制写入：现存条目只能由本次创建的所有权集合授权更新。禁止更改系统默认 Keychain、搜索列表或锁屏设置。
3. 在同一测试进程内禁用 Keychain 授权弹窗。验证重复创建不覆盖、并发创建仅一方成功，以及真实密钥库参与加密备份/错误口令拒绝/成功恢复/旧密钥与旧代次保留/状态重新打开。此次不声称 OS 进程重启或 WebView 成功业务验收。
4. 正常或 panic 路径清理本次拥有的条目，并回查缺失。超时或外部强杀若留下条目，只报告精确清单，不能扩大删除范围。构建离线且沿用隔离策略；原生执行只解除 securityd 的进程连接阻断，继续禁止直接外网、真实资料文件读取与系统操作。
5. 只运行新增测试、必要的编译/Clippy/格式检查。若产品出现 bug，先补 RED 回归再修复。更新代码图谱、PRD、进度与本地 Git。UI 仍排最后；注册、部署、付款暂停。

执行结果：入口编译、Clippy、格式及启用保护通过；受限进程无默认 Keychain（-25307），首次创建被拒绝。成功恢复保持 WAIT，成功创建数 0、条目清单为空。详见 `output/no-account-20261027/native-keychain/README.md`。
