## 3. 核心行为合同

### 3.1 检查、诊断和启动

报告含 PRD 的 14 个稳定 ID，每项返回 status、reason、observed_at、duration、valid_until、network_generation 和脱敏 evidence。GUI、CLI 和 guardian 使用相同策略。

总截止 30 秒；STUN 截止 10 秒。必需项超时、缺项、重复或待确认时阻止启动。IP 变化、ASN 暂缺使用提示策略。传输、HTTP 访问结果、账号登录状态分开记录。

启动前核对网络代次与报告有效期。证据最多使用 30 秒；网络变化立即使相关证据过期。启动动作在生命周期锁内执行，确认目标 Claude.app 身份和进程状态。

STUN 校验事务 ID、来源、长度及地址族；保留全部超时、有效响应和解析失败的区别。DNS、TUN 和服务路由各自提供实际证据。0dcloud 与 Clash Verge 的 GUI/guardian 使用同一适配模块。

独立诊断显式接受 HTTP/SOCKS 代理。默认清理环境代理继承；SOCKS 的本地/远端 DNS 行为写入结果。TLS 使用正常校验。输出分类覆盖连接、DNS、TLS、401、403、超时和代理鉴权。

### 3.2 账号事务和恢复

保持 accounts/A、accounts/B 路径。新增元数据放 v2。首次非空活动资料沿用收编 A 合同；归属未知且活动目录为空或缺失时保留已有 A。不安全路径和冲突事务保留资料并停止。兼容切换不增加迁移备份或 Keychain 调查门槛。

账号修改、启动、更新安装、发行替换共用生命周期文件锁。账号事务在其中执行；guardian 停止通道绕开长事务锁。文件锁由 OS 在崩溃后释放，事务阶段由 journal 恢复。

切换前完全退出 Claude。校验用户、目录类型、同卷条件、可用空间、权限、xattr、符号链接及目标目录身份。保留受支持的文件属性。

活动目录与归档目录各自在目标卷内准备私有暂存副本。事务日志记录原、目标及暂存目录身份。各路径保留自己的交换与恢复合同，不保证跨卷单步原子交换。每次实际交换前持久化意图。

```text
prepared → swap_intent → swapped → state_committed → completed
                             ↑
                      中断后按目录身份恢复
```

兼容读取优先采用安全有效的 current A/B 标记。标记缺失或内容不识别时回退 v2/active-state.json；不安全文件拒绝；需要回退 v2 时，损坏记录拒绝。旧目录事务与 v2 事务各保留原提交点及 journal 恢复；v2/active-state.json 不是全部兼容路径的唯一权威。重启先恢复事务，再开放新操作。

交换完成且目录身份正确时，恢复流程完成提交；身份冲突或日志损坏时保留目录和快照，进入明确的恢复入口。真实资料上避免猜测回滚方向。

文件及父目录按平台能力同步。进程终止、重启和断电分别取证。F_FULLFSYNC 的使用由实际耐久性验证决定。旧程序在 Rust 接管期停止写入同一目录。

账号切换不查询 Keychain。兼容准备投影接受核心 VerifiedPreserved 与 HandlingPlanAvailable，保留 Unresolved、后端 blocker 和 ready=false。backup_allowed 固定 false，旧备份入口明确返回未完成。准备状态不授予启动许可。旧 in-place/account/repair/install journal 恢复继续保留。

GUI 账号选择与 CLI switch 均先检查环境，通过后退出 Claude、切换资料，再复检并请求启动。普通修复一次点击生成并执行计划，成功后全检查；地区变更保留选择与确认。启动仍验证真实环境证据，失败时不启动。

### 3.3 guardian、helper 和安装

首版每台 Mac 安装一个发行，并登记一个 owner_uid。Personal/Public 的 Bundle ID、配置、更新端点与密钥独立。安装器发现另一发行时，进入显式替换流程。

guardian 使用 owner_uid 运行。网络事件触发复核，十秒兜底。停止请求针对所属用户的已识别 Claude 进程。休眠唤醒触发复核。用户直接 systemsetup 校时模块已删除；健康、事件、停止与受信 Public 更新调度保留。实际时延另验。

root 时区看门狗模板保留 RunAtLoad 与 StartInterval=3600。helper 保留固定授权校时能力。旧保镖与用户 guardian 的停止执行者未在本轮合并；安装和恢复继续核验各服务归属。

helper 使用固定产品服务标识和 root 保护目录。安装器写入 root 所有的 owner_uid、发行身份和兼容版本配置。用户级请求无法重写该安装记录。

安装记录使用 schema2 的显式信任类型。DeveloperId 使用 Apple anchor、Team 和固定 Bundle ID。SourceLocal 使用 generation 及本次 GUI、guardian、helper 的精确 CDHash；Bundle ID 由固定角色导出。旧 schema1 开发记录拒绝并要求重新安装，不隐式降级。

XPC 双端在连接激活前设置系统 peer requirement，helper 再逐消息验证角色对应签名。连接 EUID 必须匹配 owner_uid。会话关联用于拒绝已失效或无关连接。SourceLocal 只允许 GUI 与 guardian 身份，不提供独立 Installer 客户端身份。恶意客户端、错误 UID、错误签名和未知操作各有拒绝用例。

固定操作包括读取所需系统状态、应用已确认地区/网络策略、受控服务状态变更。路径固定，参数用枚举或系统列表校验。系统命令逐参数调用；系统文件使用固定模板。

同机发行替换顺序：退出 Claude → 备份配置 → 停止旧 guardian → 安装新身份与服务 → 核对健康 → 提交发行配置。失败时恢复已验证的旧包和服务。安装、卸载、更新共用这一套协调流程。

本地构建仅产出当前 Mac 的原生单架构。GUI、helper 和 guardian 使用 ad-hoc 签名及 Hardened Runtime；组件内嵌固定 identifier 和版本。管理员确认计划后，本地安装器在 root 私有暂存目录重新验证工件，整体备份和替换 App、两个组件、两个服务模板及安装记录。使用生命周期锁、root 操作锁和持久事务记录。源码重建必须重新登记指纹，普通 XPC 不得修改登记。

安装期间只开放经过身份验证的只读健康握手，普通 root 操作保持封锁。安装器取得新 GUI 和新 guardian 的实际 XPC 身份证据后，复验工件与服务再提交。失败或中断必须可恢复，重复恢复不得删除未变更组件。验收权限、ProgramArguments、服务注册、授权成功和取消。卸载默认保留账号，恢复记录过的系统原值并报告冲突。

DeveloperId 分支继续通过签名 PKG 和系统 Installer 安装 helper。该分支的商业签名及公证条件不适用于 SourceLocal。

验证等级分别记录：隔离测试、本地构建签名、SourceLocal 管理员安装与实际双进程 XPC、Developer ID 安装。隔离结果不能替代实际本机接管。未做 Developer ID 安装不阻塞源码交付或已验证的 SourceLocal 使用。

## 4. 两发行更新与发布合同

### 4.1 数据、来源和验证

本节的远程自动更新合同适用于 DeveloperId 安装及配置的可信发布源。SourceLocal 两版使用“拉取源码、重新构建、本地管理员安装”升级；不自动检查、下载或安装远端更新，更新界面明确显示此路径，不创建远程下载或安装任务。Public 的原自动更新能力保留，不新增自动执行远端源码的服务。

Personal 默认零更新检查请求。每次检查、下载、安装均由本人操作。Public 每 12 小时检查，可自动下载；安装需持有生命周期锁，确认 Claude 完全退出、账号事务空闲和组件兼容。

Public 的周期由已有用户 guardian 驱动，保存下次检查时间。检查和安装复用同一桌面可执行文件的固定更新入口；CLI update 也调用该入口。入口仅接受固定操作枚举，通过生命周期锁合并重复任务。窗口关闭或桌面进程退出后，guardian 仍可唤起该入口；需要授权时再展示界面。Personal 的 guardian 跳过此周期。E08 验证窗口关闭、进程退出、登录重启、重复触发和暂停后的行为。

使用三层现有验证：完整发布元数据 Ed25519；Tauri 工件 Minisign；Apple 应用/安装身份。保留每层明确职责和独立测试。

签名 envelope 携带完整原始 payload 字节。限制大小后先验签，再严格解析；全部嵌套对象拒绝重复键、未知字段和超限数据。元数据绑定发行、通道、平台、架构、版本、序号、有效期、key_id，以及具名 app/可选 helper 工件。

每个工件记录固定 URL、大小、SHA256、版本、Bundle/Team 身份和兼容范围。下载限制源和重定向；验证失败时删除或隔离暂存文件。

updater 2.14.0 固定 requireSignedVersion=true、allowDowngrades=false。应用层验证的候选驱动同一次下载和安装。同一份工件字节通过哈希、Minisign、Apple 身份验证后才交给安装协调器。

app.tar.gz 与 helper PKG 分别验证，按兼容顺序安装。helper 变更需要系统 Installer 的授权流程。取消授权保留旧组件健康状态。

### 4.2 状态与恢复

持久保存最高认证序号、该 payload 哈希、候选状态和安装事务。同序号只接受相同字节。过期或回放候选拒绝。时钟异常按 §5.3 的本地恢复流程处理。

失败记录采用一个有界 JSON 文件，按 app/helper 工件哈希组合保存失败原因。安装或健康失败后，自动调度跳过相同字节；更高序号重发同字节仍跳过。显式重试显示原因并由本机用户触发。

临时下载错误使用退避；授权取消可再次操作。回退只使用已验证的本地兼容版本，最高认证序号保留。安装中断、健康检查和回退失败均进入具体恢复状态。

正常密钥轮换采用桥接版本。先验证本地测试密钥跨两个历史版本升级。对外发布前验证正式桥接与独立 Apple 签名、公证的离线恢复包。软件密钥与广告密钥独立。

固定版本依据保留在既有审查记录；执行时核对锁定版本的 [updater 配置](https://raw.githubusercontent.com/tauri-apps/plugins-workspace/updater-v2.14.0/plugins/updater/src/config.rs) 与 [验证实现](https://raw.githubusercontent.com/tauri-apps/plugins-workspace/updater-v2.14.0/plugins/updater/src/updater.rs)。依赖变化时更新对应测试。

## 5. 广告、发布器与时间

### 5.1 数据与图片

三个固定 slot：residential_broadband、account_service、kyc_service。slot 完整唯一；每组至多两期；合计六期。campaign ID 唯一，同 slot 时间区间互斥。

签名清单含 schema_version、channel、content_revision、key_id、issued_at、expires_at、release_id、三组内容及素材哈希。清单最长有效 90 天。原始 payload 字节验签和严格解析复用 §4.1 的有界处理。

客户端清单上限 256 KiB。图片只接受静态 PNG/JPEG，下载上限 1 MiB、总像素上限 200 万。验证文件头、尺寸、溢出、MIME 和哈希，显式拒绝 APNG。

发布器用成熟库归一化素材、去除多余元数据，并满足相同上限。客户端采用受支持的解码器限制，限制并发解码。200 万像素 RGBA 原始缓冲最多约 8 MB；实际进程 RSS 单独测量。超限、坏文件、动画和格式混淆均有负向用例。

内容源和公钥随软件固定。广告文字按文本展示。商家目标使用 HTTPS，统一解析；拒绝 userinfo、IP 字面量、localhost、非公开主机形式和非 443 端口。IDN 展示规范化主机。merchant_id 或 normalized_host 变化后，首次点击确认。

清单和素材请求限定产品内容源。商家链接由系统浏览器打开，携带公开活动字段；用户账号、设备和代理资料保持零附加。

### 5.2 运营与托管

Personal 使用本地草稿、同组件预览、发布历史和 Keychain 凭据。运营模块只编译进 Personal。Public 构建同时移除运营 commands、页面、依赖能力和写入配置。

选用一个具备匿名读取、鉴权写入、对象版本、条件写入、公开回读的静态存储。先验证用户实际拥有的服务。R2/S3 为候选，选定后只实现一个适配器。费用核对同时覆盖广告与软件工件。

首版直接使用存储提供的写入接口。自建服务、数据库和多云切换留待出现实际需求。凭据经安全输入进入 Keychain；最小写入范围仅覆盖所选环境的广告目录。

preview/production 独立路径及凭据权限。图片按内容哈希保存；签名版本文件不可变。发布器读取 current 和 ETag，以条件写入一次提交完整新 current。ETag 冲突后提示重新读取和合并。

```text
草稿 → 共用预览 → 上传素材 → 保存不可变签名版本
                                   ↓
                              CAS 提交 current
                                   ↓
                           公开回读 → 保存发布记录
```

每次发布使用 release_id。重试沿用该 ID。结果未知时先认证 current，再回查版本、哈希和 ID。已提交同一版本时只补齐不可变对象，不再次 CAS。发布成功需要公开入口的完整签名内容与素材回读通过。不可继续的 pending 保存为有界终态记录；它不冒充发布成功，也不丢弃认证水位。

暂停、全下架、恢复历史都生成更高内容序号。全下架清单不再依赖旧素材。单张导入与下载最多 1 MiB；加密备份容器最多 64 MiB，均包含边界值。备份包含草稿、历史、素材索引和加密密钥；恢复先回读正式序号，再补传缺失素材和发布。

本地索引上限为 256 条历史和 128 个素材。手动整理默认保留 128 条历史，不执行自动过期删除。草稿、pending、保留历史、两份认证 current 和终态记录共同保护素材。pending 允许只读预览，但阻止整理提交。释放终态记录须显式选择，并绑定预览摘要。

索引整理与文件回收各需一次预览和确认。第一次确认保存固定回滚检查点，并原子提交索引与批次。第二次确认只处理该批次的精确候选。后端在同一 publication 锁内认证两份 current。候选进入私有隔离槽后重验文件身份及完整 hash，再删除隔离槽；未知文件和其他代际不参与。完成前同步两个目录。异常保留批次，重启后可以继续；不声称这些模拟等同断电验收。

活动批次的写入为最多 128 个候选身份预留编码空间。容量不足时在写检查点前拒绝。读取既有状态的兼容门槛不变。备份剥离批次字段，活动目标拒绝备份恢复。该合同依赖产品进程遵守锁与私有目录约定，不承诺抵御恶意同 UID 修改目录或进程。

```text
读取认证 current → 预览引用与候选 → 确认索引整理
                                         ↓
                               检查点 + 活动批次
                                         ↓
                    预览回收 → 确认回收 → 同步目录 → 结束批次
                                  │
                                  └→ 异常保留，重启后继续
```

内容源、公钥、模板或 schema 的不兼容修改通过软件发布。日常商家、图片、文本、链接和排期通过广告发布。

### 5.3 调度与本地时间恢复

每次成功后保存下一计划：15 分钟 + 当周期一次 0–60 秒 jitter。唤醒继续剩余时间，到期才补查。失败退避为 1/5/15/30/60 分钟，之后每 60 分钟。手动刷新设 30 秒间隔并合并请求。

current 的 CDN 缓存最多 60 秒。健康连续在线、首轮成功时，20 分钟内采用；休眠、断网和重试单列。只验证成功的响应刷新 last_success。

离线展示截止为 last_success+24h、campaign.ends_at、manifest.expires_at 三者最早值。最高内容序号和同序号哈希持久化。

排期依据系统 UTC；同进程持续时间使用可跨睡眠的单调时钟。保存最后成功 UTC 检查点。跨重启回拨超过 5 分钟，或运行中 UTC 与单调时间差变化超过 5 分钟时，时间状态进入待恢复。

时间异常时收起广告，暂停软件安装。页面说明观察到的时间差，并提供系统日期设置入口。用户校时后明确点击“重新建立时间基线”；随后从固定源获取签名内容，核对序号和有效期再恢复。清单序号、发布序号和失败工件记录保留。

首版采用这条本地人工恢复路径。时间可信假设为用户维护正确的系统 UTC。专用 time.json 服务和 HTTP Date 连续采样退出首版。合法夏令时与时区切换按 UTC 测试，避免误判。

全部广告关闭时，清单与素材请求为零。单 slot 关闭后停止其素材读取。运营者主动预览/发布的请求在对应操作中说明。
