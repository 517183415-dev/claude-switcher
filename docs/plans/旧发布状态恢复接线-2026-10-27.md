# 旧发布状态恢复接线

本阶段完成不需要真实账号的 Personal 发布数据恢复。复用现有迁移、完整归档、密码加密和目录描述符校验。注册、部署、付款及真实密钥库验证不在本阶段执行。

1. `publisher/migration.rs` 复用归档采集与导入校验；加入当前 generation 的完整归档。归档包含 state、checkpoint、assets、cleanup-gc、未索引文件、密钥包与 trust，并记录路径、类型、长度和摘要。未知项或不安全文件使整个操作失败。
2. `publisher/migration/recovery.rs` 持有 Publisher 与本机发布树锁。准备时加密、独占写入、读回解密并核对全部内容；确认摘要绑定归档、源实例及目标 current。确认时重新核对文件、密钥、实例与 current，随后原子切换代次。取消或错误释放会话；保留备份与所有旧资料。此步骤不提交远程 current；用户之后明确发布才上传。
3. `publisher_commands.rs` 与 Personal 注册/权限接入准备、确认、取消和完整归档导入。`PublisherRecovery.svelte` 提供确认界面。Public 不注册这些入口。后端在两个 IPC 调用之间持有同一个恢复对象，禁止其他发布进程修改同一资料。
4. 核心回归覆盖完整归档、口令/密文、缺项、路径/链接、源变更、锁、凭据故障、原子切换结果未知、取消及重启。阶段内只运行相关测试；阶段结束集中运行发布器测试及必要编译、类型和格式检查。

```text
原资料 + Vault + trust → 完整归档 → 加密写入 → 读回核对
                                                   ↓
                             用户确认（同一会话持锁）
                                                   ↓
                             重核对 → 新代次 → 原子切换
                                                   ↓
                                  旧资料与旧密钥继续保留
```

完整归档导入只恢复到未激活的保留目录。它不重放来源不明的旧事务，不自动外发，不清理原资料。
