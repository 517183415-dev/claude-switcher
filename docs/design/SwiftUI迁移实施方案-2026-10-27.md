# SwiftUI 迁移实施方案

状态：基础阶段已保存，整体迁移未完成。旧 Tauri/Svelte 界面仍为产品入口，不能把本阶段的原生组件当作完整迁移。

## 布局基线

当前 Personal 版左侧依次为总览、账号、环境检查、活动记录、广告运营，设置位于左下；主内容独立滚动，底部状态栏固定。Public 版不提供广告运营。总览先显示当前账号和连接路径，再显示环境概况、分类及三个广告位。其余页面保留现有分区与控件顺序。

六张 [合成数据页面截图](../../output/playwright/swiftui-layout/) 记录了迁移前的布局。截图来自浏览器预览，不证明真实账户或系统操作。

## 边界与顺序

```text
SwiftUI 页面 → 固定命令桥 → 现有 Tauri IPC/权限 → Rust 业务
      ↓                                         ↓
macOS 26 玻璃材质                         既有门禁和数据
macOS 13–25 原生材质
```

1. 在 `apps/desktop/swiftui/` 建立原生组件、命令模型和桥接测试。桥只接受固定命令，Public 版不能调用 Personal 命令。桥不保存或记录凭据。
2. 在隔离测试入口连接真实 Tauri WebView 和 IPC。确认结果、错误、异步操作与权限拒绝可返回 SwiftUI。先验证生命周期和失败路径，再接入产品构建。
3. 依照布局基线迁移各页面和弹窗。复用 Rust 数据合同、业务校验和操作门禁；不要把安全判断搬到界面层。未迁移页面仍保持原产品可用。
4. 迁移完成后验证 Personal/Public、启动与切换门禁、发布恢复和必要的缺陷回归。比较原生窗口截图，并为 macOS 13–25 保留兼容材质。
5. 只有页面、桥接、打包和验证完成后，才切换产品入口并更新 PRD、代码图谱和本地 Git。真实服务、真实账号及实际旧系统验证分别保留等待状态。

## 文件职责

- `apps/desktop/swiftui/Sources/SwitcherUI/Bridge/`：固定命令、JSON 数据和 WebView 调用边界。
- `apps/desktop/swiftui/Sources/SwitcherUI/Design/`：配色、玻璃材质和共享布局。
- `apps/desktop/swiftui/Sources/SwitcherUI/Pages/`：按页面组织的原生视图；只编排显示和操作。
- `apps/desktop/swiftui/Tests/`：桥接权限、编码及异常的核心测试；发现缺陷时增加回归。
- `apps/desktop/src-tauri/`：后续仅增加必要的原生宿主和构建接线；现有命令和权限继续生效。

不能仅用 CSS 或包裹现有网页来宣称完成 SwiftUI 重写。发布源注册、部署和付款仍暂停。

## 本阶段证据与暂停点

总览只显示合成数据，按钮不执行真实操作。命令桥已在隔离 Personal Tauri 窗口验证，但没有由产品宿主装载。其余五页、真实状态绑定、操作、宿主与打包均未完成。Public 窗口、旧系统和真实账号没有验证。详见 [验证记录](../../output/no-account-20261027/swiftui-foundation/README.md)。
