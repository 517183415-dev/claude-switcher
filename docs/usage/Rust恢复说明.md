# Rust 恢复说明

本说明采用恢复后的旧版核心行为。源码构建、真实安装和真实登录分别记录。当前状态见[实施状态](../handoff/Rust-R4-实施状态.md)。源码交付无需商业证书或公证。

## 1. 账号事务中断

1. 保留账号目录、current 文件和中断记录。
2. 完全退出 Claude。
3. 在“账号”点击恢复入口，或执行 `claude-switch.sh recover`。
4. 恢复成功后重新检查环境。
5. 核对当前账号和实际登录状态。

```text
保留现场 → 退出 Claude → 恢复中断事务 → 检查环境 → 核对登录
```

恢复使用已保存的事务阶段。它不要求先创建新的迁移备份、补充 Keychain 调查收据或重新登记安装身份。存在目录冲突、损坏记录或无法确认的中断结果时，程序保留现场并报告原因。

普通选择 A/B 会自动保存当前存档。首次切换可自动保存 A；首次使用 B 会创建空资料，供首次登录。不要为日常切换额外运行 `initialize-a`、`associate-a` 或 `migration-preview`。这些历史维护入口保留，但不构成日常使用前提。

出现忙碌提示时，先确认是否有正在运行的事务。不要手工删除锁文件或交换 A/B 目录。隔离恢复测试通过不代表真实登录已经通过。

## 2. 修复和地区设置

CLI 的 `fix`、`set-region` 默认直接执行。使用 `--preview` 才只显示计划。GUI 先显示修复计划，再由执行按钮开始操作。

用户偏好和代理文件由用户进程处理。时区、IPv6、系统服务和 DNS 缓存按需申请管理员授权。取消授权后，程序报告系统项未完成，并继续可以完成的用户项。重新运行修复即可重试，不需要因此重新安装。

`set-region` 先保存国家、时区、locale 目标和用户 locale，再申请系统授权。授权取消可能留下已保存部分，沿用旧版顺序。处理后核对目标和系统时区，再重新检查环境。

历史版本留下未完成的修复事务时，使用对应恢复入口。程序按原事务记录核对已经写入的部分。系统结果未知时保留现场。不要删除原值或回执来消除提示。新的一次普通修复不要求先完成新的安装健康登记。

## 3. 安装失败

使用[本地安装器](../../packaging/macos/README.md)处理 App、CLI 和后台组件。安装器备份旧组件。失败恢复会撤回本次组件，再恢复旧组件和服务注册。账号资料不随安装或发行替换删除。

若安装器报告冲突，保留安装日志、备份和事务目录。按日志中的具体恢复步骤处理。不要手工把用户可写的脚本放进 root 服务执行路径。

本轮先集中完成无需密码的验证，最后统一安装。真实服务注册、root 权限和跨用户停止范围，只有在统一安装后才记为本机通过。

## 4. 更新和广告

SourceLocal 不自动更新，也不接受远程二进制替换。升级时拉取源码，重新构建，再使用本地安装器安装。可信发布源中的 Personal 手动更新和 Public 自动更新分支保留，不构成本轮源码交付的材料要求。

已有广告暂停、历史恢复和加密运营备份继续保留。本轮不扩展投放或远程托管。广告恢复步骤见[广告运营说明](广告运营说明.md)。

## 5. 本地时间

时间异常会影响签名广告和软件更新。它不新增旧版检查、启动和账号切换门槛。

在系统日期设置中校正时间后，可在应用设置中重新建立时间基线。签名内容仍按序号和有效期验证。该过程保留已认证序号与失败工件记录，不需要专用时间服务。
