# Gemini 网页版整体审核材料

审核目标：原项目用 Rust 重构＋广告功能＋本地版不自动更新。先判断 PRD 和开发文档是否扩大目标，再判断代码和工作流程。

## 直接使用

1. 将 `00_复制给Gemini的提示词.txt` 的内容发给 Gemini。
2. 上传 `01_提示词及全部PRD开发文档全文.md` 与 `02_全部源码图谱流程证据.txt`。第一份已经包含提示词、代码图谱和43份需求／开发说明全文。
3. 若需要逐文件源码或完整符号关系，使用完整 ZIP；可解压后提供 `current/`、`original_HEAD/` 与 `codegraph/`，或提供对应分卷。
4. 让 Gemini 按提示词输出覆盖表、需求偏移表、旧新逻辑表和最小整改清单。若它读不完，先补齐覆盖，不能声称已经全审。

不依赖它能直接解压ZIP。TXT分卷也在包内，可按模块逐轮上传。所有材料只在本机生成，本次没有上传或发布。

## 材料含义

- `current/`：当前源码、配置、测试、实验、许可证和图标。355个文件，含全部77个Rust文件。源文件字节与导出时原仓库一致。
- `original_HEAD/`：旧项目Git HEAD 2cf108596a7bb382acbc62c2d1dd9b89e17e1d71 的31个文件。当前差异不自动归因于这一轮。
- `SOURCE_MANIFEST.json`、`diffs/`：完整哈希、行数、旧版基线差异与新增文件清单。不能只审git diff，新Rust代码大多不在原HEAD。
- `documents/`：原README、历版PRD／工程方案、现行v1.2、安装补充、使用恢复文档、交接与验收记录，共50份文件。旧版仓库没有独立PRD，不把Rust PRD v1.0自动当成用户最初想法。
- `codegraph/`：当前独立快照的完整符号／静态关系JSON及CSV，覆盖154个可解析文件。全部77个Rust文件均索引。静态边有歧义，不能作为运行证明。
- `evidence/`、`history/`：本轮恢复测试、安装、工件与窗口证据，以及最新原位补丁的前版本。保留红测，避免只呈现成功结果。

## 必须保留的审核边界

已安装20261023候选与尚未安装的20261024原位补丁候选不同。真实A建档和Claude登录页只在前者观察；后者已构建、测试及开窗。无有效登录基线，无真实B账号，不能宣称A→B→A成功。

本包包含可见用户指令账本和落盘开发记录，不是全部逐字聊天／完整工具流水，也不含每个r12–r18中间版本的完整源码。无法从现有证据确认的流程，审核者应列为材料缺口，不能推断补齐。

未包含：账号数据、钥匙串、密钥原件、真实备份、系统安装目录、编译缓存、node_modules、App二进制、旧输出目录和历史压缩包。第三方许可证和图片保留在ZIP，TXT主要提供第一方文本源码与证据。Windows／Linux旧实现、P0实验是参考材料，本轮没有承诺Rust跨平台重写。

已扫描常见私钥头和服务密钥前缀，未发现匹配。该扫描不代替人工秘密审查。原工作区没有被清理或重置。
