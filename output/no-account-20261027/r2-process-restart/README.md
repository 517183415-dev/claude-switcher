# 远程写入结果未知后的跨进程恢复

## 已验证

隔离测试使用真实 AWS SDK 和本机模拟 S3。模拟存储保存 `preview/current.json` 后断开连接。写入进程记录结果未知和待处理版本；测试终止并回收该进程，再启动新的恢复进程。新进程确认同一签名版本，匿名回读 current、历史版本和素材，并释放发布锁。两个进程使用相同的合成数据和内存密钥库。

新增父测试通过 1 项：[测试日志](r1/test.log)、[进程及版本回执](r1/receipt.json)。写入进程和恢复进程的 PID 不同；前者在后者启动前被 SIGKILL 并回收。内部工作进程不是额外的独立验收测试。

改动共享测试辅助函数后，另外两项受影响的 SDK 测试通过。桌面测试目标严格 Clippy、修改文件格式及差异检查通过：[相关检查回执](r1/related-receipt.json)。运行使用隔离 HOME、TMPDIR 和 Seatbelt，仅允许回环网络；[检查脚本](verify_related.py)记录相关命令。回执绑定测试源码 SHA256。CodeGraph 记录见 [状态](codegraph-status.json)。

## 边界

写入进程在“结果未知”记录完成后被终止。测试使用的是 Rust 测试进程，不是完整桌面 App 进程。它不验证默认 Keychain、真正的异常断电、真实 TLS、Cloudflare R2/CDN 或线上传播。模拟服务不验证服务端签名。真实账户、注册、部署和付款均未操作；AD-04 的完整验收仍待完成。
