# 排期日期解析拒绝无效输入

生产 `operations-date.ts` 曾接受不存在的日期及非编辑器日期语法。有效 RED 中，`2026-02-29T12:30` 被归一化到 3 月并返回 ok，只有日期而无时间的输入也返回 ok。见 [red.json](red.json) 与原始 [red.log](red.log)。这是解析函数的复现，没有声称实际原生日期控件允许提交同一输入。

修复在执行本地时区转换前校验输入语法和 UTC 日历字段。复用现有 invalid 返回及 Operations 的拒绝分支，不修改页面布局。保留既有 DST 规则：春季缺失时刻向后归一化，秋季重复时刻取第一次；不修改系统时区。

新增三项回归覆盖无效闰日、世纪闰年、日/月/时/分/秒越界、非 datetime-local 语法和有效输入保持。台北、洛杉矶、UTC 的测试只设置测试进程 TZ。
