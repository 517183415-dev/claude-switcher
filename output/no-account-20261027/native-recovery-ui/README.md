# 产品页面恢复确认与刷新保护

## 发现的问题

恢复确认完成后，原页面先解除操作锁，再异步读取最新草稿。读取期间，用户可能看到旧内容并开始操作。[修复前回执](r1/red-summary.json)记录了真实 WKWebView 中的失败；其产品源码哈希对应提交 `50043411`。

## 修复和验证

页面现在保持操作锁，直到最新资料读取完成。读取失败时继续锁定，并显示“重新读取恢复结果”。重试成功后才解除锁。

隔离 WKWebView 操作实际 Svelte 页面，走正式 Tauri IPC 与权限控制。测试使用合成 MemoryVault 和本机对象存储，模拟启动快照与环境检查。它通过 7 次相关 IPC 响应及 5 个磁盘检查点：[修复后回执](r2/receipt.json)。响应次数不是独立测试数量。

测试人为延迟恢复后的草稿读取，确认操作锁仍有效；再模拟读取错误，确认锁保持且重试成功。测试还验证取消保留原资料、确认不自动发布、旧代次保留，以及用户明确重新发布后的 Ed25519 签名和更高版本。合成口令没有出现在响应、运行日志、检查点或合成业务目录。`svelte-check` 为 0 错误、0 警告；产品前端及隔离测试程序构建通过。[原始检查输出](svelte-check.log)。

## 边界

这是带测试包装的产品页面和合成密钥库，不是普通生产构建。默认 Keychain、完整桌面 App 重启、真实 R2/CDN、线上传播和 AD-10 的其他分支仍待验。没有注册、部署或付款。此前全量 Rust 验证见 `storage-final-verify/current`；本次没有重复运行。
