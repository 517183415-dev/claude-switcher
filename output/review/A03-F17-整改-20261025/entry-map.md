## 3. A03 最短交互序列与边界

```text
N=128 → 预览索引整理 → 用户确认 → 执行索引整理
                                      ↓
                         第二次预览 GC → 用户确认 → 执行 GC

终态记录 → 独立显式释放终态槽 → 刷新 publisher_status
```

以上是要求的接线形态，不是当前已实现功能。UI 不应把第一次确认复用于 GC。更改 N、切换步骤或执行后，旧预览须失效。执行端应重新检查绑定状态；仅禁用按钮不能防止第二窗口或后端状态变化。不要让定时刷新、onMount、发布完成或达到容量自动触发清理/释放。

现有 `Operations.svelte:64` 文案为“历史与关联素材至少保留 90 天。”整理/GC 的新说明必须符合最终后端保留规则，不能保留与实际策略冲突的绝对承诺。fixture 模式所有新处理函数必须零 IPC，不能只依赖按钮 disabled。终态释放单独说明释放的是终态记录槽，不是删除已发布内容；未决 pending 不能通过此入口伪装完成。

当前 publisher 事实：`mod.rs:310–315` 校验 history/assets 容量；`:465–466` 达素材上限返回 `asset_capacity_no_history_pruned`；`:502–512` Status 仅有 phase/pending/recovery/history。当前入口尚无整理/GC 命令，不能称“只补一个已存在按钮”。
