| 当前事实 | 精确锚点 | 对 R05 的要求 |
|---|---|---|

最小 seam 建议：保留公开 `read_command(program,args)` 的默认两秒行为，抽出私有预算参数 runner。DNS 调用明确 DNS 预算；测试通过私有 program 注入点调用同一 runner 和同一首行解析逻辑。预算建议先在 PLAN 明定（例如外层 4 秒覆盖内部 3 秒及有限调度收尾），不提高所有系统观察命令的超时，不增加公共任意命令入口。

2.5 秒无网络 RED 方法：在测试临时目录生成 executable 假 dig，使用已存在的绝对 Python 解释器；代码仅 `time.sleep(2.5)` 后向 stdout 写 `198.18.0.1\n`，不导入 socket、不调用 dig/curl、不查询主机。直接 Python shebang，或 shell 随即 `exec` Python，避免 shell 留下 sleep 孙进程。用私有 DNS program seam 把该绝对路径传给真实 runner，仍传实际 `+short,+time=3,+tries=1,fixture.invalid` 参数。不要把返回字符串塞进 OUTPUTS fixture。旧预算应返回 observation_timeout；验收断言要求收到首行 IP，先捕获真正行为 RED。

配套隔离测试建议（全部只管理自建子进程）：

1. 立即成功、2.5 秒合法成功、超过专用预算仍挂起并被终止；用宽容调度上下界，避免精确毫秒断言。
2. 输出超过 OUTPUT_LIMIT、非零退出、非法 UTF-8、首行 CNAME 后跟 IP。断言原错误分类和首行行为不变。
3. 主动取消正在等待的 runner；记录该自建 child 的 PID/退出回执，只核对该 child 的终止与 wait/reap。既不枚举宿主进程，也不操作无关 PID。
4. 假 dig 关闭 stdout 后继续睡眠，确认预算同样覆盖 child.wait；保留普通 read_command 两秒上限的单独测试。

本轮不建议为 F08 扩展到通用进程组管理。若测试发现后代进程或取消回收需要额外生命周期设计，先报告具体证据，再缩小或批准范围。

## F10：当前 YAML 合同与识别缺口

实际编辑键是顶层 `prepend-rules`，不是泛化的 `rules`。`propose` 是纯 bytes→proposal，不写文件。现有 header 命中只去 CR/LF，要求整行等于 `prepend-rules:`（`pinned_routes.rs:215-229`）；其余输入会在原文前新增同名块。
