账号事务采用“准备 → 保存快照 → 验证目标 → 记录交换 → 交换 → 提交 current → 清理”的持久状态。中断恢复先核对日志和目录哈希，再选择完整状态。目录交换的具体 API 由 P0 固定。跨卷导入先复制到目标卷，再进入交换阶段。

## 5. 三条关键执行链

### 5.1 检查、账号与启动

1. 获取统一写入锁，并检查待恢复事务。
2. 组合 CLI 先检查环境；账号切换确认 Claude 完全退出。
3. 保存快照并准备目标资料，按持久检查点交换目录。
4. 提交 current，再检查网络代次和证据有效期。
5. 条件满足后启动；条件变化时显示等待原因。

```text
业务请求 → 锁与恢复 → 检查/退出 → 快照和交换 → current
                                                   |
                     启动 ← 新鲜检查证据 ← 网络代次核对
```

P0-05 先识别目录外依赖。具体 Keychain 项名、ACL 与迁移方式以本机证据为准。账户资料读取限于获批真实迁移任务所需范围。验收日志采用合成标记和摘要。

### 5.2 系统修复与服务交接

helper 通过已验证 PKG 安装。系统 Installer 完成授权。安装后核对 receipt、签名、属主、权限、版本与健康状态。

XPC 校验收到消息的对端签名、Team ID、允许 Bundle ID、用户、协议和操作。测试覆盖有效客户端、其他签名、临时签名、错误用户和协议冲突。helper 仅接受固定时区、网络及服务动作。

时区来自本机有效列表。网络服务来自本机枚举。执行参数逐项传递。服务描述来自已验证安装包。来源于用户目录的 plist 始终按普通输入处理。

guardian 使用用户身份。网络变化触发重查，2 秒周期检查兜底。停止通道独立于长复制任务。目标为可检测异常发生后 5 秒内发出停止请求；记录实际最大值及测试负载。

### 5.3 软件与广告分别发布

| 流程 | 触发 | 签名与提交 | 恢复 |
| --- | --- | --- | --- |
| Personal 软件 | 本人点击检查和下载，确认安装 | 固定自控源；包签名与完整元数据；空闲及兼容条件 | 原兼容程序与服务组合；保留最新资料 |
| Public 软件 | 默认 12 小时检查 | 验签后等待 Claude 退出和写入空闲；需要新权限时显示系统授权 | 自动回退记录；保留最高发布序号 |
| 广告内容 | 本地运营页发布 | 本地签名；上传素材和不可变版本；CAS 提交完整 current；公开入口回读 | 历史内容发布为更高序号 |

更新器候选启用 `requireSignedVersion=true`，关闭降版本安装选项。元数据绑定 edition、channel、OS、arch、version、hash、sequence、expiry、key ID。验签成功后进行严格 schema 解析。重复键、未知字段、退序、过期和相同序号异内容分别拒绝。

软件密钥正常轮换使用桥接版本。应急恢复使用独立 Apple 签名、公证的离线安装包。广告密钥恢复通过独立的软件信任流程交付。P4 需分别演练。

## 6. 广告托管与日常运营

### 6.1 候选部署

Sites 为优先验证候选，S3 静态内容源为备选。该决定保持“待 P0 实测”。Apple Developer 用于签名身份；内容托管用于分发公开文件。当前采购、创建站点及部署次数均为 0。

```text
Personal 运营页 → 本机签名 → 鉴权发布接口 → R2 / S3
                                            ├─ 素材哈希路径
                                            ├─ 不可变发布版本
Public → 固定公开 HTTPS 路径 ←───────────────└─ current
```

| P0-06 验证项 | 操作与通过标准 | 失败处理 |
| --- | --- | --- |
| 读取身份 | 从桌面无登录环境读取公开清单和图片，返回预期内容 | 调整公开读取入口或选备选托管 |
| 写入身份 | 正确凭据写入；缺失、过期、错误权限凭据被拒绝 | 收紧服务端授权；保持发布待验证 |
| 条件提交 | 两个发布者共用旧 ETag，只有一次 current 提交成功 | 改为具备原子条件写入的适配器 |
| 一致性与缓存 | 上传完整版本后回读；验证 CDN 失效和健康在线 20 分钟目标 | 缩短缓存、增加再验证或调整入口 |
| 恢复和成本 | 备份后恢复历史；核对账号配额、文件上限、带宽和预计费用 | 写出容量预算与替代路径再决策 |

Sites 的本地文档说明支持 Workers、D1、R2 和自定义域名。R2 的 `onlyIf` 提供条件写入。实际选定账户、站点模式和公网入口仍待验证。[R2 官方接口](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)、[S3 条件写入](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html)

广告私钥保存在运营者本机。发布服务验证调用权限，并限制环境、路径、体积和请求内容。服务端取得的是已签名清单及公开素材。软件安装包托管另行测量体积和带宽。

接收方可见到达它的出口地址、时间和正常协议元数据。验收重点是应用主动读取并发送的资料字段、目标和远端响应引起的本地动作。

### 8.3 证据格式和判定

每条证据记录任务 ID、验收 ID、提交及差异哈希、锁文件哈希、机器/系统/架构、执行时间、输入条件、结果、日志/截图位置、执行者与复核者。

状态固定为 PASS、FAIL、WAIT、NOT_RUN、OBSERVING。PASS 绑定具体用例和环境。编译成功、隔离回归、原生集成、真实账号、外发载荷、长期观察分别记录。

UI 依次验证组件、浏览器渲染、实际 Tauri 窗口、macOS 原生操作和真实应用流程。测试桥接只进入测试构建。对应官方路径见 [Tauri WebDriver](https://v2.tauri.app/develop/tests/webdriver/)。

## 9. 本机迁移与恢复操作单

1. 保存旧程序、配置、服务、权限和账号快照，核对恢复材料。
2. 退出 Claude，确认写入空闲，生成配置和资料迁移预览。
3. 按文本解析旧字段，写入 v2 配置，保留 A/B 存档结构。
4. 安装验证后的程序及服务，核对身份、版本、资料和真实启动。
5. 保存新状态与回退说明，开始 48 小时及随后 7 天观察。

```text
旧版基线 → 最终快照 → v2 导入 → 服务交接 → 真实 A
   ^                      |            |
   └──── 恢复程序与兼容资料 <──── 验收失败
```

新版使用后回退，先保存最新资料。恢复程序时按数据兼容表选择资料版本。任何自动回退都保留失败版本、原因和最高认证发布序号。
