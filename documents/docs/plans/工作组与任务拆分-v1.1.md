版本：v1.1。日期：2026-10-22，America/Los_Angeles。状态：**第三轮审核已处理；新会话按执行提示词组织实现。**

本文件将“组方案”落实为五个工作组。它与[PRD](PRD-Rust双版本产品-v1.1.md)、[工程执行文档](工程执行文档-Rust重写-v1.1.md)配套。总体架构沿用[主方案 v2.3](rust-rewrite-plan.md)。

## 1. 组织与责任

总负责人管理产品范围、共享接口、风险决定、集成顺序和最终交付。Gemini 承担本轮独立方案复审。用户将工程提示词交给新会话并要求实施后，进入该基线的执行范围。P0 分支门槛和跨组接口详见 [工程合同补充](工程合同补充-v1.1.md)。

| 工作组 | 目标 | 主责范围 | 主要评审方 |
| --- | --- | --- | --- |
| G1 核心与账号组 | 保留账号资料，统一检查和事务 | domain、checks、accounts、config、migration、diagnostics、CLI | G5；平台接口由 G3 复核 |
| G2 桌面与体验组 | 实现已确认 UI 和清晰的中文操作 | Svelte、Tauri commands/capabilities、类型绑定、广告运营页面 | G5；合同由 G1 复核 |
| G3 macOS 与服务组 | 完成签名身份、安装和系统操作 | platform、XPC、guardian、helper、PKG、代理适配 | G5；更新交接由 G4 复核 |
| G4 发布与广告组 | 实现两种更新策略及三广告位运营 | updates、ads、publisher、发行配置、内容源、密钥恢复流程 | G5；安装边界由 G3 复核 |
| G5 验证与交付组 | 提供独立、可复查的完成证据 | 合成资料、集成用例、外发记录、兼容矩阵、观察记录 | 总负责人；争议项提交 Gemini/用户 |

五个工作组表达责任划分。可以由同一人员分阶段承担。需要独立复核的任务，由另一执行者阅读结果。并行数量服从接口就绪和文件归属。

```text
用户确认文档 ← Gemini 独立复审
      |
  总负责人：范围 / 集成 / 风险 / 最终验收
      |
      ├─ G1 核心与账号 ─┬─ G2 桌面与体验
      ├─ G3 macOS服务 ─┘
      ├─ G4 发布与广告
      └─ G5 独立验证 ─────> 阶段证据与交付判断
```

## 2. 文件归属与协作规则

| 文件范围 | 唯一修改负责人 | 其他组的接入方式 |
| --- | --- | --- |
| 根 workspace、Cargo.lock、toolchain、domain（含 ads 模型） | G1 | 提交具体依赖或合同变更请求 |
| core 的 checks/accounts/config/migration/diagnostics、CLI | G1 | 平台和 UI 通过既定接口接入 |
| desktop 全部源码、前端锁文件、Tauri 配置 | G2 | G1/G3/G4 提供合同和适配需求 |
| platform、service、packaging/macos | G3 | 业务组请求窄能力，提供参数及场景 |
| core 的 updates/ads、publisher、editions、release、ad-content | G4 | G2 消费模型；G3 提供安装能力 |
| tests/acceptance、tests/fixtures、docs/acceptance | G5 | 实现组提交场景；G5 维护综合矩阵 |
| 模块内单元用例和样例 | 对应模块负责人 | G5 复核覆盖及实际结果 |
| docs/adr、PRD、执行文档和任务索引 | 总负责人，指定单次编辑者 | 变更带需求、影响和验收说明 |

1. 开始任务前确认依赖、文件范围和验收编号。
2. 其他组已有修改予以保留，接口差异交负责人协调。
3. 共享文件由唯一负责人整合，交叉任务使用明确交接记录。
4. 合并前提交改动摘要、执行证据和剩余状态。
5. 完成后复核来源版本、证据路径和下一组进入条件。

后续若创建分支或 worktree，名称带任务编号。一次集成只包含一个可验收结果。提交采用仓库 Lore 格式，记录原因、约束和实际验证状态。

## 3. 每组任务卡

### G1 核心与账号组

| 项目 | 要求 |
| --- | --- |
| 输入 | PRD 的 CK/AC/UP 合同；旧版 21 个测试意图；P0 账号依赖证据 |
| 任务 | P0-05a/b、P0-07a/b；P1-01～P1-03；P2-01；支持 P2-02、P3-01、P3-04、P4-05 |
| 输出 | domain、CLI、检查/诊断、账号事务、迁移和类型合同 |
| 验收 | F-01～F-08、F-10；F-09 依据第二账号条件；PR-06/07 的核心侧 |
| 交接 | G2 得到类型和状态 fixture；G3 得到平台能力清单；G5 得到阶段状态与恢复入口 |

首个工作包：完成一个检查从平台接口到 CLI JSON 的闭环，再交 G2 接环境页。首个资料工作包：以虚拟档案验证初始化和恢复，再进入真实 A。

目录外依赖待确认时，G1 先完成合成资料事务。真实迁移入口保持 WAIT。不得猜测具体 Keychain 项名或替换用户凭据。

## 5. 交接单与问题台账

每次交接使用以下五项。内容直接写入对应任务记录。

1. **目标与版本：** 任务 ID、需求 ID、源版本、工作区差异和工件哈希。
2. **交付范围：** 修改文件、公开接口、兼容要求和配置变化。
3. **验证证据：** 命令、环境、输入、实际结果、日志和截图路径。
4. **未决事项：** FAIL/WAIT/NOT_RUN、触发条件、影响和负责人。
5. **接手动作：** 下一任务、所需材料、恢复路径和进入条件。

| 问题级别 | 定义 | 处置 |
| --- | --- | --- |
| 阻塞 | 影响资料完整性、发布身份、远程执行控制或主要流程 | 暂停对应集成，修复并独立复核 |
| 需修正 | 需求或交接合同缺项，尚有可执行替代路径 | 负责人修订并登记影响 |
| 待材料 | 证书、托管、第二账号或指定平台环境未到位 | 标记 WAIT，推进独立任务 |
| 建议 | 影响效率或后续扩展 | 评估成本，列入当前或后续范围 |

Gemini 的意见按证据归类。每条记录“采纳/部分采纳/待澄清/保留原设计”、原因、修改位置和复核结果。存在不同结论时，列出可验证条件。
