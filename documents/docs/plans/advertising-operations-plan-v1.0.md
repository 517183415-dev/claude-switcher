# 广告管理与后续更新方案

版本：v1.0。日期：2026-10-22，Asia/Taipei。关联主方案：v2.2。

**首版提供你自己使用的“广告管理”页。你修改内容、预览并点击发布后，对外客户端会获取新广告。日常修改广告沿用同一软件版本。**

本文件是待实施方案。所有时间、刷新指标和验收条件均为设计目标。

## 1. 你以后怎样更新广告

入口设在自用版左侧的 **运营 → 广告管理**。默认打开本地草稿。主界面广告关闭时，管理与预览仍可使用。

1. **选择广告位。** 选择美国家庭宽带、注册好的账号或 KYC 服务。
2. **编辑内容。** 填写商家、标题、说明、按钮、链接；上传图片；设置投放时间。
3. **预览效果。** 查看正式尺寸、小窗口和下一期内容；核对链接与变更摘要。
4. **点击发布。** 管理页校验、签名、上传并回读，显示发布结果与内容版本。
5. **管理后续状态。** 查看当前与下一期广告；暂停某个广告位；恢复历史内容。

```text
你在自用版编辑
      -> 本地预览
      -> 校验并签名
      -> 你的广告内容源
      -> 对外客户端验签刷新
```

### 1.1 三个广告位各自管理

| 广告位 | 固定 ID | 独立配置 |
| --- | --- | --- |
| 美国家庭宽带 | `residential_broadband` | 商家、内容、图片、链接、当前期、下一期、上下架状态 |
| 注册好的账号 | `account_service` | 商家、内容、图片、链接、当前期、下一期、上下架状态 |
| KYC 服务 | `kyc_service` | 商家、内容、图片、链接、当前期、下一期、上下架状态 |

每个广告位首版支持“当前一期”和“下一期”。同一时刻每个广告位展示一条广告。发布前检查时间重叠，并要求明确选择保留或替换哪一期。

账号服务采用官方授权服务内容。KYC 广告采用用户本人实名协助内容。商家介绍与广告素材在管理页编辑。

### 1.2 管理页包含什么

| 区域 | 显示内容 | 可用操作 |
| --- | --- | --- |
| 发布概况 | 预览/正式环境、内容版本、最后发布时间、内容源域名 | 检查发布状态；查看历史 |
| 三个广告位 | 当前内容、下一期内容、起止时间、上架状态 | 编辑；预览；暂停；安排下一期 |
| 编辑表单 | 商家、标题、说明、图片、按钮、HTTPS 链接 | 保存草稿；测试链接；清除图片 |
| 发布预览 | 新旧差异、受影响广告位、桌面/小窗口效果 | 发布到预览环境；发布到正式环境 |
| 发布历史 | 发布编号、时间、内容摘要、结果 | 查看快照；用历史内容创建新版本 |

页面显示的是内容源发布结果。全量客户端采用情况需要独立统计设计。首版通过自用版的“检查正式内容”验证可下载与可展示状态。

## 2. 发布系统怎样组成

### 2.1 首版结构

| 组件 | 放置位置 | 职责 |
| --- | --- | --- |
| 广告管理页 | 自用版，运营专用构建能力 | 编辑、排期、预览、签名、上传、撤回、历史恢复 |
| 本地草稿与历史 | 自用版运营数据目录 | 保存草稿、签名清单与发布记录；支持导出备份 |
| 发布凭据 | macOS Keychain 或本人控制的密钥存储 | 保存广告签名私钥与内容源写入凭据 |
| 广告内容源 | 本人控制的 HTTPS 域名、静态存储与 CDN | 提供签名清单、不可变版本和图片 |
| 广告展示模块 | 对外客户端 | 获取整份清单、验签、本地筛选、缓存和展示 |

自用版普通启动保持零广告请求。预览、发布、检查正式内容均由你的操作触发。对外版按用户的广告展示设置自动获取内容。

首版采用一个运营者、两个内容环境：preview 与 production。基础管理页计入首版交付。多商家登录、协作审批、订单与结算列为后续功能。

### 2.2 固定数据与发布字段

| 层级 | 字段 | 规则 |
| --- | --- | --- |
| 清单身份 | `schema_version`、`channel`、`content_revision`、`key_id` | 预览与正式环境分别校验；内容序号递增 |
| 时间 | `issued_at`、`expires_at` | 以 UTC 保存；清单有效期覆盖已排期内容，最长 90 天 |
| 广告记录 | `slot_id`、`campaign_id`、商家、标题、说明、按钮 | 三个固定广告位；当前期与下一期最多六条记录 |
| 投放计划 | `starts_at`、`ends_at`、`enabled`、可选服务地区 | 每期都有结束时间；同一广告位时间区间互斥 |
| 素材与链接 | 图片路径、SHA256、格式、尺寸、HTTPS 目标 | 图片使用内容哈希路径；链接采用公开活动编号 |
| 发布封装 | 完整 payload 与签名 | 验签绑定原始 payload 字节；同序号内容须逐字节一致 |

运营界面使用你选择的时区，初始为 Asia/Taipei。保存时转换为 UTC。客户端按同一时刻执行排期。用户修改系统时间后，客户端重新检查时间可信状态；异常时收起广告并提示待刷新。

清单大小、图片大小与解码预算沿用主方案 2.5。先校验完整清单，再生成展示状态。未知 schema 返回具体错误，并保留有效缓存或使用占位卡。

### 2.3 内容源与凭据

第一阶段使用提供对象版本、原子覆盖和条件写入能力的静态存储。对外读取走固定 HTTPS 路径。P0 按这些能力选择具体服务，并记录费用估算。

发布权限只覆盖广告目录。preview 与 production 使用独立路径及写入范围。广告签名密钥与软件更新密钥分别管理。

对外安装包包含广告公钥、读取端点和展示模块。发布凭据、签名私钥和运营写入模块仅进入你的自用运营构建。

| 发起方 | 目标 | 发送内容 |
| --- | --- | --- |
| 自用版发布器 | 本人的静态存储写入接口 | 广告清单、签名、图片、版本条件和必要发布鉴权 |
| 自用版发布回读 | 本人的公开广告域名 | 固定版本与素材读取请求 |
| 对外客户端 | 本人的公开广告域名 | 清单和素材读取请求；字段沿用主方案的外发清单 |
| 测试链接操作 | 用户选择的系统浏览器 | 广告目标链接及公开活动编号 |

广告签名私钥保持在本机密钥存储。发布鉴权只发送至已配置的存储接口。预览采用示例账号状态。日志对鉴权字段做脱敏，账号资料外发验收覆盖发布器和展示模块。

日常更换商家、文字、图片、按钮、链接和排期通过广告内容发布完成。修改清单结构、客户端模板、信任公钥或内容源域名时，走软件版本发布流程。

## 3. 发布、定时更新与撤回

### 3.1 一次发布的完整顺序

1. **准备候选。** 读取当前正式版本，以它为基准编辑三个广告位。校验时间、文字长度、图片和链接。
2. **完成预览。** 使用客户端同一渲染组件预览。可发布到 preview，再由自用版读取确认。
3. **上传素材。** 上传内容哈希命名的图片。回读核对哈希后，保存不可变的签名版本文件。
4. **提交当前版本。** 用条件写入把固定 `current.json` 一次性替换为完整签名封装。基准版本变化时显示冲突，重新合并后发布。
5. **回读并记账。** 从公开入口回读，验证版本、签名和素材。成功后保存发布记录；结果未知时先查询同一发布编号。

```text
本地草稿
   -> 预览校验
   -> 上传图片和版本文件
   -> 条件替换 current.json
   -> 公开入口回读
   -> 发布完成 / 待确认 / 失败
```

建议的静态内容结构如下，具体域名在 P0 登记：

```text
广告域名/
  preview/current.json
  production/current.json
  preview/releases/<内容序号>.json
  production/releases/<内容序号>.json
  assets/<图片 SHA256>.<格式>
```

`current.json` 将 payload 与签名放在同一个对象中。客户端获取到完整版本后再验签。上传中断时，未提交的素材保留为暂存；正式入口继续提供前一版本。

每次发布生成唯一发布编号。网络重试沿用同一编号。管理页用远端序号和哈希判断提交是否已经成功。

### 3.2 客户端何时刷新

| 场景 | 设计行为 |
| --- | --- |
| 对外版正在运行、联网、至少一位广告开启 | 每 15 分钟检查整份清单，加 0–60 秒随机延迟 |
| 启动或从睡眠恢复 | 距上次成功检查超过 15 分钟时补查；同一进程合并重复请求 |
| 内容源缓存 | `current.json` 缓存时间最多 60 秒；图片按哈希长期缓存 |
| 正常在线传播 | 自发布回读成功起，持续运行、联网且广告开启的客户端，目标 20 分钟内更新 |
| 手动刷新 | 广告设置页提供“刷新广告”，连续操作合并并设置 30 秒间隔 |
| 请求失败 | 依次在 1、5、15、30、60 分钟后重试；之后按 60 分钟重试 |
| 无网络 | 有效缓存最多使用至上次成功检查后 24 小时，并受广告结束时间与清单有效期约束 |
| 全部广告关闭或应用已退出 | 停止广告刷新；下次启用或启动时按规则检查 |

软件更新继续采用每 12 小时检查。广告内容使用独立的 15 分钟刷新周期。这项调整替代 v2.1 中广告每 12 小时刷新的设计。

广告请求保持固定公开路径和空查询参数。地区筛选在本机执行。客户端保留最高已验签内容序号，拒绝更小序号和同序号的不同内容。

只有通过传输、签名、序号和有效期检查的响应才更新成功检查时间。缓存过期后显示本地占位卡。接收暂停指令后，立即清除该位的可点击展示状态。

### 3.3 定时上下架

你可以提前填写下一期广告及开始时间。发布后，客户端依据清单中的 UTC 时间切换。你的电脑可以在发布后关闭。

每个广告位独立结束。广告到期后，客户端显示已排定的下一期；没有下一期时显示占位卡。客户端关闭广告位的本地偏好继续生效。

90 天清单期限临近时，管理页在打开后提醒续发。续发会签署新的内容序号。长期广告可通过“沿用内容并续期”重新发布。

### 3.4 暂停、撤回与恢复

| 操作 | 发布方式 | 客户端行为 |
| --- | --- | --- |
| 暂停一个广告位 | 发布新序号，将该位标为暂停 | 下次成功刷新后收起该位广告 |
| 全部紧急下架 | 发布新序号，将三个广告位全部标为暂停 | 在线客户端按刷新周期获取；离线客户端按缓存期限处理 |
| 恢复历史内容 | 读取历史快照，复核链接与排期，以更高序号发布 | 按正常刷新流程采用新版本 |
| 发布中断 | 通过发布编号查询远端状态，继续同一候选或保留旧版本 | 客户端继续使用已经验证的版本 |
| 当前内容源异常 | 运营端显示具体失败，客户端采用有效缓存或占位卡 | 主功能照常使用 |

暂停通常由你在管理页完成一次发布。传播时间按上表的在线条件验收。处于断网或退出状态的客户端，在恢复后获取最新状态。

历史快照和所引用素材至少保留 90 天。回滚时若素材缺失，管理页先补传并验证。首版由运营者主动清理无引用素材，清理前显示候选清单。

### 3.5 密钥与内容恢复

你的备份包含草稿、发布历史、已签名内容及加密的广告密钥备份。恢复后先回读正式序号，再创建下一次发布。

广告私钥失效时，暂停运营写入，核对最近发布记录。新的广告公钥通过独立的软件更新信任流程交付。收到新软件版本的客户端再接受新广告密钥。

## 4. 模块与实施安排

### 4.1 模块划分

| 模块 | 责任 | 构建范围 |
| --- | --- | --- |
| `switcher-domain/ads` | 清单模型、广告位枚举、时间规则、内容序号 | 自用版与对外版共享 |
| `switcher-core/ads` | 获取、验签、缓存、排期和展示资格 | 自用版预览与对外版读取 |
| `switcher-ad-publisher` | 草稿、签名、存储写入、冲突检查、发布记录、历史恢复 | 自用运营构建 |
| desktop 运营页面 | 三广告位编辑、预览、发布时间与结果 | 自用运营构建 |
| 发布适配器 | 内容源上传、条件写入、回读与版本查询 | 运营模块通过窄接口调用 |

管理页与客户端共用广告预览组件。运营发布使用独立本地锁和远端条件写入。它读取广告草稿、素材与发布凭据。

### 4.2 分阶段交付

| 阶段 | 增补工作 | 证据 |
| --- | --- | --- |
| P0 | 确定域名、存储、缓存策略、签名与凭据位置；验证原子写入和条件写入 | 配置清单、能力验证记录、预估费用 |
| P1 | 三广告位管理表单、本地草稿、两种窗口预览 | 表单状态、预览截图、离线草稿 |
| P4 | preview/production、签名上传、15 分钟刷新、排期、撤回、恢复 | 两次发布、一次暂停、一次历史恢复与外发记录 |

相对 v2.1，基础广告管理增加 **4–6 个工程工作日**。其中本地管理与预览约 1–2 天，发布与刷新约 2–3 天，专项验收约 1 天。主方案工程估算更新为 **27–37 个工作日**，P0 再校准。

### 4.3 首次配置材料

| 材料 | 用途 | 准备时机 |
| --- | --- | --- |

| 广告目录写入凭据 | 从管理页发布内容 | P0/P4，以安全输入存入密钥存储 |

## 5. 验收标准

下表为实施验收计划。当前交付为文档。

| ID | 场景 | 通过标准 |
| --- | --- | --- |
| AD-01 | 分别修改三个广告位 | 每次只改变选定内容；其余两位与版本快照一致 |
| AD-02 | 编辑、预览、发布 | 表单可保存草稿；正式客户端展示与预览一致；软件版本保持原值 |
| AD-03 | 预览与正式环境 | 预览发布只改变 preview；正式发布需显示明确目标与变更摘要 |
| AD-04 | 上传中断、重试、并发发布 | 正式入口始终提供完整签名版本；重复发布可恢复；过期基准触发冲突提示 |
| AD-05 | 连续在线刷新 | 在约定缓存、网络和运行条件下，发布回读成功后 20 分钟内采用新版本 |
| AD-06 | 时间与排期 | 同一 UTC 时刻下，台北和其他时区展示一致；开始、结束、下一期和重叠检查正确 |
| AD-07 | 暂停与历史恢复 | 暂停单卡与全部下架可生效；恢复历史内容使用更高序号；本地关闭偏好保持 |
| AD-08 | 离线、过期和错误响应 | 超过 24 小时缓存限制、投放结束或清单到期时收起广告；无效签名与倒退序号被拒绝 |
| AD-09 | 出站请求与发行包 | 对外包仅含读取能力；账号标记、发布凭据和私钥外发为 0；全部关闭后广告请求为 0 |
| AD-10 | 发布备份与恢复 | 恢复发布记录后可读取正式序号、补传素材并发布下一版本；敏感备份保持加密 |

关联：[Rust 主方案](rust-rewrite-plan.md)。下一步在 P0 确定内容源和签名配置，随后按上述里程碑实现。
