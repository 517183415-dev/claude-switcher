# Personal 本机广告运营

用户已选择先在本机运营。当前唯一实际适配器是 `LocalObjectStore`。
它使用固定用户私有目录，不需要 R2、S3、云账号或网络凭据。
`protocol::ObjectStore` 保留一个发布接口，没有预建多云架构。

## 操作

1. 在 Personal 的「广告运营」编辑三个广告位。每位最多两期，UTC 排期不能重叠。
2. 点击「生成广告签名密钥」。此明确操作把私钥存入 macOS Keychain；打开草稿不会生成密钥。
3. 导入 PNG/JPEG，检查图片和链接，再发布到本机预览或本机正式。
4. 本机预览保存到隔离预览目录。两个发行的普通广告区读取本机正式目录。
5. 暂停或恢复历史后，再发布到本机正式。历史恢复生成更高序号，不回退旧清单。

两个发行仍分别保存广告开关与商家确认。需要开启广告位并确认用途，才显示广告。
本机正式发布不向其他设备或远程用户投放。远程上线仍是 WAIT。

```text
Personal 草稿 ── Keychain 签名 ── 不可变版本/素材
                                    |
                           本机 current 原子 CAS
                                    |
                            签名与素材回读验证
                                    |
                   Personal / Public 各自验证后展示
```

## 固定目录与安全边界

- 草稿：`~/.claude-switcher/v2/personal/publisher`。
- 本机发布：`~/.claude-switcher/v2/local-ads/{preview,production}`。
- 公共验证材料：`local-ads/trust.json`，只含 schema、固定 key_id 和公钥。
- 客户端缓存：`v2/{personal,public}/ads`。Public 不创建或修改 `local-ads` 发布树。
- 私钥：Keychain。备份密码、私钥和凭据不进入命令参数、日志或普通配置文件。

「公共验证材料」指同一用户的两个发行共享的公钥。发布文件仍是 0700 目录内的 0600 私有文件。
目录、文件所有者、链接、权限和读取上限均接受校验；IPC 不接受源路径或任意 URL。
素材与版本用同卷 `renamex_np(RENAME_EXCL)` 原子创建；既有内容不同则冲突。
`current.json` 用文件哈希作 ETag，在同一生命周期锁内比较并原子替换。
任何提交写盘错误均视为结果未知；重试先回查同一个 release_id。
签名清单、不可变版本与所有素材回读全部通过后，才记录成功历史。
客户端不建立本机 HTTP 服务，不发送本机内容网络请求。
客户端仍检查签名、channel/key_id、最高序号、UTC、素材哈希与静态图片限制。
坏广告只收起广告并显示原因，不阻断账号工作台。

## 加密备份与恢复

备份采用 Argon2id 与 XChaCha20-Poly1305，包含草稿、历史、素材及 Keychain 私钥材料。
备份文件本身加密；请保存密码并复制到安全位置。
错误密码或不合格备份不会切换代际。恢复到未配置密钥的新草稿目录也可导入备份内的验证公钥。
已有不同公钥时拒绝覆盖。恢复后，正式发布先回读本机正式最高序号，再补齐素材并续发。
恢复旧备份不会降低本机已认证最高序号。

## 验证与限制

最新本地证据见 `docs/acceptance/evidence/e10/local-publisher-tests.log` 和 E09 的 `local-ad-runtime-tests.log`。
测试使用真实临时文件存储及内存 Vault，不写真实 Keychain。
测试覆盖 CAS、不可变对象、锁替换、硬链接/符号链接/宽权限拒绝、重启、两发行读取、暂停、历史、预览隔离和加密恢复。
真实原生窗口、实际用户明确生成 Keychain 密钥后的发布，应另记现场证据。
真实远程 HTTPS、云端权限、CDN 传播与连续 20min 在线验收仍 WAIT。
未来只有用户明确要求远程投放后，才选择一个服务并核对其条件写、固定 HTTPS 源和授权材料。
